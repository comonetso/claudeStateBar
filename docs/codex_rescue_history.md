# codex_rescue 스킬 작업 이력 (2026-08-17 ~ 2026-09-16)

`codex_rescue` 스킬은 2026-09-16 전까지 별도의 비공개 작업 공간에서 고쳐 왔다. 그날부터 스킬 수정은
이 레포의 세션에서 한다. 스킬은 원격 서버에도 배포되고, 공개 사본(`skills/codex_rescue/`)과 사용 가이드,
진행 패널이 모두 이 레포에 있어서 함께 관리해야 하기 때문이다.

이 문서는 그 이전 작업의 요약과, 아직 닫히지 않은 항목의 목록이다. 원문 세션 로그는 비공개 작업 공간에
남아 있다(서버 이름·경로가 많이 들어 있어 옮기지 않았다).

## 스킬을 고치는 순서

1. 편집 원본은 `~/.claude/skills/codex_rescue/` 다. 실제로 발동되고 서버로 배포되는 것이 이것이다.
   고치기 전 백업은 스킬 폴더 밖(`~/.claude/_backups/`)에 둔다. 스킬 폴더 안에 두면 서버까지 배포된다.
2. 서버 배포는 `/skill_cp_install deploy`. 삭제는 전파하지 않는다.
3. 공개 사본은 `node tools/sync-codex-skill.js` 로 맞춘다(`--dry-run` 으로 미리보기).
   서버 이름·호칭·개인 경로를 가리는 규칙은 레포 밖 로컬 파일에 있고, 남은 표기가 있으면 아무것도 쓰지 않고 멈춘다.
4. 사용자에게 보이는 동작이 바뀌면 `docs/codex-rescue-guide.md`·`.ko.md`, README 영/한, CHANGELOG 를 함께 고친다.
5. 스킬이 남기는 파일 이름이 새로 생기면 진행 패널의 삭제 목록(`src/providers/codexRescue/runDiscovery.ts` 의
   `runLogNames()`·`followupExtras()`)도 같이 고친다. 이걸 놓쳐 1.15.1 까지 파일 세 종류가 삭제 뒤에 남았다.

## 날짜별 요약

**2026-08-17 — 자동 왕복 구축.** 요청서를 사람이 두 번 옮기던 구조를 `send.sh` 하나로 자동화했다
(Codex 호출 · 응답 회수 · 변경 실측 · 자동 재호출). 분석·리뷰·수정 세 모드와 한국어 뜻으로 모드를 고르는 판정을
넣었다. Windows 에서 Codex 가 파일을 못 읽던 샌드박스 고장(에러 1332)을 `unelevated` 설정으로 고쳤다.
OpenAI 공식 Claude Code 플러그인과 비교한 뒤 설치하지 않기로 했고, 리뷰 기능은 CLI 내장 명령으로 흡수했다.
Codex 에 스킬 자체를 두 차례 검토시켜 버그 15건을 반영했다.

**2026-08-25 — 대폭 개편.** "Claude 가 Codex 를 자기 생각 안에 가둔다"는 문제를 두 가지로 풀었다.
하나는 되묻기(한 건에 최대 11턴)이고, 다른 하나는 프롬프트가 스스로 막고 있던 권한을 푼 것이다
(디스크 읽기·`.scratch/` 쓰기·네트워크 조회). 요청서는 원본 경로를 앞에, Claude 의 가설을 뒤에 짧게 두도록 바꿨다.
네트워크 기본 허용, 턴 상한 11, `danger-full-access` 미사용은 사용자 결정이다.

**2026-08-26 — 핑퐁 `--look` 자료 미전달 버그 수정.** 핑퐁에 실어 보낸 파일이 Codex 에 전달되지 않던 문제를 고쳤고,
라인 범위 없이도 파일을 실을 수 있게 했다.

**2026-09-02 — 배포 방식 변경 반영.** 스킬 배포가 GitHub 경유에서 SSH 직접 전송(`deploy`)으로 바뀐 것을 문서에 반영했다.
스킬 발동 문구를 좁히자는 제안은 사용자가 "불편한 적 없다"고 해서 그대로 두기로 했다.

**2026-09-13 ~ 14 — 한도 인지.** 요금제 한도를 절반쯤 쓴 상태에서 부른 분석이 도중에 끊겨 결과가 날아간 일이 계기다.
실행 전에 모델·추론 수준·한도를 조회해 한 번 묻는 절차, 모델·추론 수준 지정(`CR_MODEL`·`CR_EFFORT`),
조사하면서 응답 문서에 적어 나가는 중간 저장, 끊긴 실행의 판정(`status: partial`·`stop_reason`)을 넣었다.
한도 흔적을 로그 전체에서 찾던 판정은 Codex 가 읽은 파일 내용 때문에 오탐이 나서, 구조화된 이벤트만 보도록 바꿨다.
사람이 턴을 멈춘 경우를 구분하고, 멈춘 실행을 다른 모델로 되물어 이어가는 것까지 실측했다.

**2026-09-15 — 끼어들기 확장.** 실행 중 끼어들기를 분석뿐 아니라 수정·리뷰의 첫 턴까지 넓혔다.
리뷰는 전용 명령이 도중 입력을 받지 않아서, 요청서를 자동으로 만들어 Codex 공식 리뷰 기준으로 일반 턴처럼 돌린다.
수정 결과에 되물어 추가로 고치는 기능(`edit: yes`, 턴마다 승인)과, 끼어들기 경로의 네트워크 개방을 넣었다.
Windows 샌드박스의 네트워크 차단은 프록시 환경변수 방식이라, 프록시를 따르지 않는 프로그램에는 효과가 없다는 것을 확인했다.

**2026-09-16 — 확인 강제·조회기·자격증명.** 실행 전 확인을 건너뛴 실사례가 나와 `CR_CONFIRMED=1` 이 없으면
실행을 거부하게 했다. 한도 조회기를 WebSocket 대신 stdio 로 바꿔 Node 20 서버에서도 조회되게 했다.
Codex 가 요청서의 DB 조회를 못 하던 원인이 권한이 아니라 프롬프트의 "자격증명 파일을 열지 마라" 문구였음을 찾아,
"읽기는 허용하되 값은 문서·출력에 남기지 않는다"로 바꿨다.
같은 날 이 레포로 수정 거점을 옮기고, 공개 사본·가이드를 따라잡고, 진행 패널의 삭제 누락을 1.15.2 에서 고쳤다.

## 아직 닫히지 않은 것

검증이 안 된 것
- 실제 한도 초과로 끊긴 실행에서 `stop_reason: limit` 이 나오는지, 리셋 뒤 이어가기가 되는지 (억지로 재현하지 않는다)
- 수정 모드의 중간 저장본
- Codex 가 자격증명을 읽고 실제로 DB 에 접속하는지
- 서버에서의 수정·리뷰 끼어들기, Node 20 서버에서의 끼어들기 실제 왕복
- 무거운 모델·높은 추론 수준에서의 리뷰 품질
- 리뷰 범위 지정(`--base`·`--commit`)의 실제 실행 (미리보기까지만 확인)
- 여러 파일이 얽힌 수정 모드
- 예전 방식 리뷰(`codex exec review`)에 모델·추론 수준 옵션이 적용되는지

사용자가 일부러 미룬 것
- 응답 파일 없이 최종 메시지만 남으면 종료 코드를 보지 않고 성공으로 분류하는 문제
- 한도 조회기가 리셋 시각의 1초 흔들림을 리셋으로 오판해 과거 소모 계산에서 실행을 빼는 문제

진행 패널 쪽
- 끊긴 실행이 `실패`로만 보이고, 결과 문서가 중간본이라는 표시가 없다
