# codex_rescue — Codex에게 2차 의견 받기

> 이 문서는 **claudeStateBar 확장의 "Codex 진행 상황" 패널**과 짝을 이루는
> `codex_rescue` 스킬 사용 안내입니다. 스킬 자체는 확장에 포함되어 있지 않습니다 —
> 확장은 스킬이 남긴 실행 기록을 **보여주는 쪽**입니다.
>
> English version: [codex-rescue-guide.md](codex-rescue-guide.md)

`codex_rescue`는 Claude Code용 스킬입니다. 내가 만든 코드나 Claude가 막힌 문제를
**다른 AI(Codex)에게 검증받습니다.** 말로 시키면 되고, 주고받는 건 전부 자동입니다.

---

## 0. 설치

### 필요한 것

- **Claude Code** — 스킬이 도는 곳입니다
- **Codex CLI** — `npm i -g @openai/codex` (이 문서는 `0.145.0` 기준입니다)
- **Windows라면 Git Bash** — `send.sh`가 POSIX 셸 스크립트입니다

### 스킬 받기

```bash
mkdir -p ~/.claude/skills/codex_rescue
BASE=https://raw.githubusercontent.com/comonetso/claudeStateBar/main/skills/codex_rescue
curl -fsSL "$BASE/SKILL.md" -o ~/.claude/skills/codex_rescue/SKILL.md
curl -fsSL "$BASE/send.sh"  -o ~/.claude/skills/codex_rescue/send.sh
chmod +x ~/.claude/skills/codex_rescue/send.sh
```

레포를 통째로 받았다면 `skills/codex_rescue/` 를 `~/.claude/skills/` 로 복사해도 됩니다.

Claude Code를 다시 열면 `/codex_rescue` 가 잡힙니다. 확장의 진행 패널도 이때부터 나타납니다.

### 🔴 설치 전에 알아둘 것

이 스킬은 **`codex exec` 를 `-s workspace-write` 로 실행합니다.** 즉 Codex가 워크스페이스
파일에 쓸 수 있는 상태로 돕니다. 그래서 확장에 번들하지 않고 직접 설치하도록 두었습니다.

- 기본 모드(분석·리뷰)에서 Codex는 **응답 문서 하나만** 쓰도록 지시받고, 그 외 변경은
  스크립트가 파일시스템으로 **실측해 보고**합니다 (6절 참조).
- 그래도 프롬프트를 안 지킬 가능성을 아예 없애고 싶다면 `CR_SANDBOX=read-only` 로 쓰십시오.
  Codex에게 쓰기 권한을 주지 않고, 최종 메시지를 스크립트가 대신 저장합니다.
- 코드를 직접 고치는 **수정 모드는 기본 차단**이며 승인 없이는 스크립트가 거부합니다.

## 1. 세 마디만 알면 됩니다

| 이렇게 말하면 | 무엇을 보나 | Codex가 코드를 |
|---|---|---|
| **"리뷰시켜"** | **바뀐 코드 전부** (git diff) | 안 고침 |
| **"분석해줘"** | **막힌 문제 하나** | 안 고침 |
| **"분석하고 수정시켜"** | 위 + 직접 고침 | **고침** (승인 필요) |

정해진 키워드가 아닙니다. **뜻으로 알아듣습니다.**
"바뀐 거 훑어줘" · "커밋 전에 봐줘" → 리뷰. "이거 왜 안 되는지 물어봐" → 분석.

Claude가 **어느 쪽으로 알아들었는지 한 줄로 밝힙니다.** 틀렸으면 "그게 아니라 이거야"로 바로잡으면 됩니다.

---

## 2. 손댈 일이 없습니다

Claude가 Codex를 직접 부르고, 끝나면 알아서 받아 검토합니다.
붙여넣기도, "다 됐다"고 알려줄 일도 없습니다.

**도는 동안 다른 일을 시켜도 됩니다.** 보통 1~3분 걸리는데 그 사이 멈춰 있지 않습니다.

⚠️ 단 **세션을 닫으면 자동 인식이 끊깁니다.** 결과 파일은 남으니 다음에 그 경로만 주면 이어서 봅니다.

---

## 3. "리뷰"와 "분석"은 대상이 다릅니다

이걸 구분해야 헛돌지 않습니다.

| | **리뷰** | **분석** |
|---|---|---|
| 대상 | **바꾼 코드 전부** | Claude가 **막힌 문제 하나** |
| 준비물 | **git 레포여야 함** | 아무 데서나 됨 |
| Codex가 받는 것 | git diff | **Claude의 가설 + 이미 실패한 시도** |
| 언제 쓰나 | 커밋·배포 전 점검 | 몇 번 해봐도 안 될 때 |

**분석이 핵심인 이유** — 요청서에 "Claude가 원인을 뭐라 봤고, 뭘 해봤다 실패했나"가 들어갑니다.
그게 없으면 Codex는 **Claude가 이미 걸어간 길을 그대로 되밟습니다.** 시간만 쓰고 답은 같습니다.

리뷰 범위는 알아서 잡습니다 — **커밋 안 한 게 있으면 그것을, 깨끗하면 기본 브랜치와 비교.**
따로 정하고 싶으면 말하면 됩니다: "main 기준으로 리뷰해" · "이 커밋만 리뷰해"

> 💡 **요청은 작게 주는 게 훨씬 빠릅니다.** 실측으로 확인된 차이입니다 —
> 커밋 안 된 변경 전체를 리뷰시키면 Codex가 파일마다 명령을 돌려 **20분**이 걸렸고,
> 판단이 필요한 코드만 요청서에 담아 물었더니 **1분 25초**에 끝났습니다(명령 36건 → 4건).
> 급할 때는 "이 함수만 봐줘"처럼 좁혀서 물으십시오.

## 4. 결과는 파일로 남습니다

프로젝트의 **`docs/codex_rescue/`** 에 쌓입니다.

```
260817_210036_review_auth-refactor.md        ← 코드 리뷰 결과
260817_182041_request_fcm-token-null.md      ← Claude가 쓴 요청서
260817_182041_response_fcm-token-null.md     ← Codex 답변 + Claude 검토
.log/260817_182041_events.jsonl              ← 실행 중 실시간 기록 (진행 패널이 읽는 것)
```

**Codex 원문은 손대지 않고 Claude 검토를 아래에 덧붙입니다.**
나중에 "Codex가 실제로 뭐라 했나"를 잃지 않습니다. git에도 올라가니 다음 세션이 그대로 이어받습니다.

**`.log/` 는 스킬이 자동으로 git에서 제외합니다** — 디렉토리를 만들 때 그 안에 `.gitignore`
(내용 `*`)를 함께 떨굽니다. 명령 출력·MCP 인자·에이전트 메시지 전문이 담겨 유출 위험이 있고
크기도 크기 때문입니다(한 번 실행에 105줄 / 409KB 측정). 요청서·응답 md는 한 단계 위에 있어
영향받지 않고 그대로 커밋됩니다.

### 쌓이는 양과 정리

실행 한 번에 **약 300KB**씩 쌓이고, 그중 86% 정도가 명령 실행 결과 전문입니다.
**기본은 영구 보관이며 아무것도 자동으로 지워지지 않습니다.**

claudeStateBar 확장을 쓰신다면 두 가지 방법이 있습니다.

- **수동** — 진행 패널의 카드에서 🗑. 원시 기록만 지울지 문서까지 지울지 **매번 물어봅니다.**
  끝난 실행에만 버튼이 나타납니다
- **자동** — 설정에서 `codexRunAutoCleanup` 을 켜면 확장이 시작될 때 1회 정리합니다
  (기본 보관 7일). 진행 중이거나 lock이 남은 실행은 절대 건드리지 않습니다

## 5. 진행 상황을 눈으로 봅니다 (claudeStateBar 확장)

예전에는 Codex가 도는 몇 분 동안 무엇을 하는지 전혀 보이지 않았습니다.
이제 확장이 **실행 중인 활동을 실시간으로** 보여줍니다.

**여는 법** — 상태바 클릭 → `Codex 실행 N건`, 또는 `Ctrl+Shift+P` → `claudeStateBar: Show Codex Runs`

보이는 것:

| | |
|---|---|
| **말 / 생각** | Codex가 "이제 뭘 하겠다"고 말한 문장 — 가장 쓸모 있는 정보입니다 |
| **명령** | 실행한 명령과 종료 코드 |
| **검색 · 파일 · MCP** | 웹 검색어, 건드린 파일, 도구 호출 |
| **계획** | Codex가 계획을 세운 경우에만 `2/5` 형태로 |
| **알림** | CLI 안내 메시지 — **오류가 아닙니다** |

상태는 `시작 중 → 진행 중 → 마무리 중 → 완료 / 실패 / 중단 / 응답 없음` 으로 바뀝니다.

- **마무리 중**이 따로 있는 이유: Codex의 턴이 끝나도 스킬은 변경 검사·응답 회수·로그 보존을
  더 합니다. 그 구간을 "완료"로 표시하면 아직 안 끝난 걸 끝났다고 하는 셈입니다.
- **응답 없음**은 프로세스가 강제 종료된 정황입니다. 완료로 승격하지 않습니다.
- 끝나면 **완료음**이 울립니다 (설정: `claudeContextBar.workflowCompleteBeep`).

⚠️ **진행률(%)은 표시하지 않습니다.** Codex는 앞으로 도구를 몇 번 부를지 미리 알리지 않기 때문에
전체 진행률은 원리적으로 계산할 수 없습니다. 대신 경과 시간과 활동 수를 보여줍니다.

## 6. Codex는 마음대로 못 고칩니다

"수정시켜"가 아니면 **코드를 건드리지 않습니다.** 말로만 막는 게 아닙니다 —
실행 전후 파일을 **실측 비교**해서, 응답 파일 말고 뭐가 바뀌었으면 보고합니다.

발견해도 **알아서 되돌리지 않습니다.** 되돌릴지 살릴지는 사용자가 정합니다.

**"수정시켜"라고 해도 바로 안 고칩니다.** 승인 전에는 **스크립트가 거부합니다.**
예전에는 Claude가 "진행할까요?" 묻는 게 약속일 뿐이라 잊으면 그냥 고쳐졌습니다. 지금은 코드가 막습니다.

### 변경 감지가 못 잡는 것

"응답 파일 외 변경 없음"은 **"감시 범위에서 최종 상태 차이가 없었다"**는 뜻입니다. 다음은 통과합니다.

- 제외 영역 내부 — `.git` · `node_modules` · `build` · `.gradle` · `.dart_tool` · `.venv` · `.next` · `__pycache__`
- 생성 후 삭제, 기존 파일의 mtime 원복
- 실행 종료 후 자식 프로세스가 만든 지연 변경
- **원인 귀속 불가** — 다른 프로세스나 동기화 도구의 변경과 구별할 수 없습니다

더 엄격하게 막으려면 `CR_SANDBOX=read-only`를 쓰십시오. Codex에게 쓰기 권한을 아예 주지 않고,
최종 메시지를 스크립트가 응답 파일로 저장합니다.

## 7. 함정

- **리뷰는 git 레포에서만 됩니다.** 아니면 "분석해줘"로 물으십시오
- **리뷰 지적을 다 고치지 마십시오.** 오탐과 취향 문제가 섞입니다. 골라서 적용합니다
- **범위와 집중 지시를 같이 못 줍니다** (Codex CLI 제약)
  "main 기준으로 인증 위주로 리뷰해"처럼 둘을 같이 주면 범위가 덜 정확하게 들어갑니다.
  **범위가 중요하면 집중 지시 없이** 시키는 게 낫습니다
- **답이 왔다고 다 성공은 아닙니다** — Codex가 "파일을 못 읽었다"고 답하는 경우가 있습니다.
  Claude가 내용까지 확인하지만, 답이 이상하면 로그를 보라고 하면 됩니다
- **`error` 로 표시되는 게 다 오류는 아닙니다** — CLI 안내 메시지가 같은 채널로 옵니다.
  패널에서는 `알림`(노란 점)으로 구분해 보여줍니다

### 아직 검증되지 않은 것

| 기능 | 상태 |
|---|---|
| 기본 왕복 (분석·리뷰·전달·회수·자동 재호출) | ✅ 실측 |
| 수정 모드 (Codex가 직접 고치기) | ✅ 실측 — 단 **1줄 수정 케이스**. 여러 파일이 얽힌 변경은 미검증 |
| 진행 패널 · 완료음 · 실시간 갱신 | ✅ 실측 |
| `main 기준으로 리뷰해` · `이 커밋만 리뷰해` | ❌ 미리보기만 |
| Linux 서버에서 실제 실행 | ❌ 설치·문법만 확인 |
| Remote-SSH 워크스페이스의 진행 패널 | ❌ 미지원 (확장이 로컬 파일만 읽습니다) |

## 8. 안 될 때

| 증상 | 원인 · 해결 |
|---|---|
| "git 레포가 아니다" | 리뷰는 git 전용. **"분석해줘"로 바꿔** 물으면 됩니다 |
| "리뷰할 변경이 없다" | 커밋을 다 했고 기본 브랜치면 볼 게 없습니다. `이 커밋만 리뷰해`처럼 대상을 주십시오 |
| **Codex가 파일을 못 읽는다** | Windows 샌드박스 계정 문제(에러 1332). 스킬이 `windows.sandbox=unelevated`로 우회합니다. 그래도 안 되면 `~/.codex/config.toml`을 확인하십시오 |
| 답이 이전 것과 똑같다 | Codex가 이번엔 아무것도 못 쓴 것입니다. `stale`로 잡아 알려줍니다 |
| **"이미 실행 중"이라고 거부된다** | 같은 걸 두 번 동시에 돌린 것입니다. 먼저 것이 끝나길 기다리십시오 (파일 덮어쓰기 방지) |
| 패널에 아무것도 안 보인다 | 그 워크스페이스에서 아직 한 번도 실행하지 않은 것입니다. 한 번 돌리면 나타납니다 |
| 진행이 실시간으로 안 보인다 | 스킬이 구버전일 수 있습니다. 실시간 기록은 나중에 추가된 기능입니다 |

---

## 9. 환경변수

| 변수 | 용도 |
|---|---|
| `CR_MODEL=<모델>` | Codex 모델 지정 |
| `CR_SANDBOX=read-only` | Codex에게 쓰기 권한을 주지 않음 (가장 안전) |
| `CR_ALLOW_EDIT=1` | 수정 모드 해금 — **승인 후에만** |
| `CR_DRYRUN=1` | 실행하지 않고 조립된 명령만 확인 |
