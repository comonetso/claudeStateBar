# codex_rescue — Codex에게 2차 의견 받기

> 이 문서는 **claudeStateBar 확장의 "Codex 진행 상황" 패널**과 짝을 이루는
> `codex_rescue` 스킬 사용 안내입니다. 스킬 자체는 확장에 포함되어 있지 않습니다 —
> 확장은 스킬이 남긴 실행 기록을 **보여주는 쪽**입니다.
>
> English version: [codex-rescue-guide.md](codex-rescue-guide.md)

`codex_rescue`는 Claude Code용 스킬입니다. 내가 만든 코드나 Claude가 막힌 문제를
**다른 AI(Codex)에게 검증받습니다.** 말로 시키면 되고, 주고받는 건 전부 자동입니다.

---

## 0. 설치

### 필요한 것

- **Claude Code** — 스킬이 도는 곳입니다
- **Codex CLI** — `npm i -g @openai/codex` (이 문서는 `0.145.0` 기준입니다)
- **Windows라면 Git Bash** — `send.sh`가 POSIX 셸 스크립트입니다

### 스킬 받기

```bash
mkdir -p ~/.claude/skills/codex_rescue/scripts/lib
BASE=https://raw.githubusercontent.com/comonetso/claudeStateBar/main/skills/codex_rescue
curl -fsSL "$BASE/SKILL.md" -o ~/.claude/skills/codex_rescue/SKILL.md
curl -fsSL "$BASE/send.sh"  -o ~/.claude/skills/codex_rescue/send.sh
chmod +x ~/.claude/skills/codex_rescue/send.sh

# 실행 중 끼어들기를 쓰려면 이 넷도 함께 받습니다 (안 받아도 나머지 기능은 그대로 됩니다)
for f in live-consult.mjs lib/appserver.mjs lib/bridge.mjs lib/runtime.mjs; do
  curl -fsSL "$BASE/scripts/$f" -o ~/.claude/skills/codex_rescue/scripts/$f
done
```

레포를 통째로 받았다면 `skills/codex_rescue/` 를 `~/.claude/skills/` 로 복사해도 됩니다.

Claude Code를 다시 열면 `/codex_rescue` 가 잡힙니다. 확장의 진행 패널도 이때부터 나타납니다.

### 🔴 설치 전에 알아둘 것

이 스킬은 **분석·수정 모드에서 `codex exec` 를 `-s workspace-write` 로 실행합니다.** 즉 그때는
Codex가 워크스페이스 파일에 쓸 수 있는 상태로 돕니다. 그래서 확장에 번들하지 않고 직접 설치하도록
두었습니다.

- **리뷰 모드는 예외입니다.** `codex exec review` 는 CLI 자체가 읽기 전용으로 고정돼 있어
  `-s` 를 받지도 않습니다. 리뷰 결과 파일도 Codex가 아니라 `send.sh` 가 씁니다
- 분석 모드에서 Codex는 **응답 문서 하나만** 쓰도록 지시받고, 그 외 변경은
  스크립트가 파일시스템으로 **실측해 보고**합니다 (6절 참조).
- 그래도 프롬프트를 안 지킬 가능성을 아예 없애고 싶다면 `CR_SANDBOX=read-only` 로 쓰십시오.
  Codex에게 쓰기 권한을 주지 않고, 최종 메시지를 스크립트가 대신 저장합니다.
- 코드를 직접 고치는 **수정 모드는 기본 차단**이며 승인 없이는 스크립트가 거부합니다.

## 1. 네 마디만 알면 됩니다

| 이렇게 말하면 | 무엇을 보나 | Codex가 코드를 | 걸리는 시간 |
|---|---|---|---|
| **"리뷰시켜"** | **바뀐 코드 전부** (git diff) | 안 고침 | 분 단위 |
| **"분석해줘"** | **막힌 문제 하나** | 안 고침 | 분 단위 |
| **"다시 물어봐"** | **직전 분석에 되묻기** | 안 고침 | 분 단위 |
| **"분석하고 수정시켜"** | 위 + 직접 고침 | **고침** (승인 필요) | 분 단위 |
| **"코덱스와 대화해"** | 지금 던지는 짧은 질문 | 안 고침 | **10초 안팎** |

정해진 키워드가 아닙니다. **뜻으로 알아듣습니다.**
"바뀐 거 훑어줘" · "커밋 전에 봐줘" → 리뷰. "이거 왜 안 되는지 물어봐" → 분석.

🔴 **마지막 줄만 예외입니다.** 핑퐁은 **명시할 때만** 갑니다 — "코덱스와 대화해" · "핑퐁으로 물어봐"처럼요. "코덱스한테 물어봐" 같은 기존 표현은 전부 분석(정식 자문)으로 갑니다. 가벼운 쪽이 기본이면 편하겠지만, 그러면 제대로 된 자문을 받으려던 것이 한 줄짜리 답으로 새기 때문입니다.

Claude가 **어느 쪽으로 알아들었는지 한 줄로 밝힙니다.** 틀렸으면 "그게 아니라 이거야"로 바로잡으면 됩니다.

## 2. 손댈 일이 없습니다

Claude가 Codex를 직접 부르고, 끝나면 알아서 받아 검토합니다.
붙여넣기도, "다 됐다"고 알려줄 일도 없습니다.

**도는 동안 다른 일을 시켜도 됩니다.** 작은 요청은 1~3분이면 끝나지만 범위가 넓으면
20분까지도 갑니다. 어느 쪽이든 그 사이 멈춰 있지 않습니다.

⚠️ 단 **세션을 닫으면 자동 인식이 끊깁니다.** 결과 파일은 남으니 다음에 그 경로만 주면 이어서 봅니다.

---

## 2-1. 핑퐁 — 짧게 여러 번 주고받기

위의 세 모드는 전부 **한 번 무겁게 던지고 오래 기다리는** 방식입니다. 대화 도중에 "코덱스, 넌 어떻게 생각해?" 한 마디를 던지기에는 과합니다. 핑퐁은 그 자리를 위한 것입니다.

```
✳️ 클로드: <Claude가 던진 말>
🔷 코덱스: <받은 답 그대로>
```

양쪽이 다 화면에 나오므로 오가는 걸 보면서 판단할 수 있습니다. Claude는 받은 답을 요약하지 않고 원문 그대로 옮기고, 자기 판단은 그 아래에 따로 붙입니다.

**같은 주제면 계속 이어집니다.** Codex 세션을 그대로 재개하므로 앞 턴을 다시 설명할 필요가 없습니다. 주제가 바뀌면 새 대화로 시작합니다.

### 볼 것을 지목하면 빨라집니다 (2026-08-25 개정)

예전에는 **파일 탐색을 아예 막아** 놨습니다. "탐색을 켜면 느려진다"는 이유였는데,
**320파일짜리 실제 레포에서 여섯 조합을 재보니 그 전제가 틀렸습니다.**

| 상황 | 시간 | Codex가 돌린 명령 |
|---|---|---|
| 탐색 열고 + 가벼운 질문 | **7초** | **0회** |
| 탐색 열고 + 파일명을 지목한 코드 질문 | 25초 | 1회 |
| **파일을 실어 보내고**(13KB) 같은 질문 | **8초** | 0회 |
| 파일을 실어 보내고(56KB) | 12초 | 0회 |
| 탐색 열고 + **대상 없는** 넓은 설계 질문 | **240초 초과** | **105회** |

느려지는 원인은 탐색 허용이 아니라 **"어디를 볼지 안 알려준 것"** 이었습니다.
16분씩 멈춘 것처럼 보이던 사고의 정체가 이것입니다.

**그래서 이제 Claude가 볼 파일을 지목해 직접 실어 보냅니다.** Codex는 찾을 필요가 없습니다.
실측상 **가장 빠르고 답도 가장 정확했습니다**(탐색으로 찾게 한 쪽보다 3배 빠르고 함수명까지 집었습니다).

- 한 번에 하나만 묻습니다. 부족하면 한 줄 더 던지면 됩니다 — 그게 핑퐁입니다
- **60초를 넘기면 스스로 중단합니다**(예전 120초). 위 표에서 60초에 걸리는 건 맨 아랫줄 하나뿐이라,
  걸렸다면 **지목이 빠졌다는 신호**입니다
- 무거운 질문이면 애초에 "분석해줘"(정식 자문)가 맞습니다. 억지로 핑퐁에 밀어 넣을 이유가 없습니다

### 남는 것

`docs/codex_rescue/<스탬프>_chat_<슬러그>.md` 하나입니다. 턴이 이어 붙고, 실행 기록(`.log/`)은 남기지 않습니다 — 그래서 **Codex 진행 상황 패널에는 뜨지 않습니다.** 대신 claudeStateBar 확장의 **Codex 채팅 패널**이 이 문서를 읽어 대화를 한 화면에 보여줍니다(1.11.0 이상).

Codex에게는 쓰기 권한을 주지 않습니다. 답변은 스크립트가 회수해서 문서에 적습니다.

⚠️ **대화 문서는 git으로 오가지만 Codex 세션은 따라가지 않습니다.** 다른 PC에서 시작한 대화는 그 문서가 있어도 이어받을 수 없어, 새 대화로 시작합니다. 문서에 시작한 머신 이름이 적혀 있어 자동으로 판별합니다.

## 2-2. 되묻기 — 분석은 이제 한 번으로 끝나지 않습니다 (2026-08-25 신설)

**왜 만들었나** — 같은 장애를 "분석해줘"로 **세 번** 물었는데 결론이 안 났습니다.
그런데 사용자가 Codex와 **직접 11턴 대화**하니 결론이 났습니다. **같은 모델, 같은 사고 강도였습니다.**

실행 기록을 파 보니 차이가 분명했습니다.

| | 정식 자문 3건차 | 사용자 직접 대화 |
|---|---|---|
| 사용자 발화 | **1턴** (요청서 던지고 끝) | **11턴** |
| Codex의 추론 블록 | 59 | **137** |

**차이는 모델이 아니라 턴 수였습니다.** 정식 자문은 대화가 아니라 **투척**이었습니다.
Codex가 중간 가설을 내놔도 되받는 사람이 없었습니다.

### 무엇이 달라졌나

답변을 받은 뒤 Claude가 **"내가 이렇게 읽었는데 맞나"를 다시 물을 수 있습니다.**
같은 Codex 세션을 이어가므로 **1턴에서 읽은 코드·로그·계산을 기억한 채** 답합니다.

```
1턴  Claude → 요청서        → Codex 분석
     Claude → ## Claude 검토 를 문서에 덧붙임
2턴  Claude → 그 검토를 Codex에게 다시 읽힘
     Codex  → "너는 X라고 읽었지만 나는 Y를 뜻했다"
3턴  …필요한 만큼 (상한 11턴)
```

🔴 **핵심은 `## Claude 검토`를 Codex가 읽는다는 점입니다.** 예전에는 Claude가 "이건 기각"이라고
써도 문서에만 남고 Codex에게는 안 갔습니다. **반박당할 기회가 없었습니다.**

### 언제 되묻나

Claude가 알아서 판단하지만, 기준은 이렇습니다.

- Codex 지적을 **기각했을 때** ← 기각은 되묻는 사유입니다. 기각 근거가 틀렸을 수 있고,
  Codex는 자기가 기각당한 줄 모릅니다
- Codex가 Claude 가설을 **그대로 승인**했을 때 ← 반박을 못 받았다는 뜻입니다
- 핵심 증상이 아직 설명되지 않았을 때

직접 시키실 수도 있습니다: **"다시 물어봐"** · "되물어" · "그거 반박해봐"

### 남는 것

응답 문서 하나에 턴이 이어 붙습니다.

```
## Codex 원문              ← 1턴
## Claude 검토             ← 다음 턴의 입력이 됩니다
## 🔁 2턴 — Claude 반박
## 🔷 2턴 — Codex 재답변
```

반박서는 `<스탬프>_followup<N>_<슬러그>.md` 로 따로 남습니다.
**2턴부터 Codex는 읽기만 합니다** — 문서는 스크립트가 대신 이어 붙입니다.

⚠️ **대화 문서는 git으로 오가지만 Codex 세션은 따라가지 않습니다.** 다른 PC에서 시작한 분석은
그 문서가 있어도 이어받을 수 없습니다. 문서에 시작한 머신 이름이 적혀 있어 자동으로 판별합니다.

## 3. "리뷰"와 "분석"은 대상이 다릅니다

이걸 구분해야 헛돌지 않습니다.

| | **리뷰** | **분석** |
|---|---|---|
| 대상 | **바꾼 코드 전부** | Claude가 **막힌 문제 하나** |
| 준비물 | **git 레포여야 함** | 아무 데서나 됨 |
| Codex가 받는 것 | git diff | **원본 파일의 실제 경로 + "직접 열어라"** |
| 언제 쓰나 | 커밋·배포 전 점검 | 몇 번 해봐도 안 될 때 |

**분석이 핵심인 이유** — 요청서에 **원본 자료가 어디 있는지 절대경로**가 들어갑니다.
Claude의 가설도 담기지만 **뒤쪽에 짧게만** 붙습니다.

🔴 **2026-08-25에 순서를 뒤집었습니다.** 예전에는 가설이 앞이었는데, 그러면 Codex가
**Claude의 시선 안에 갇힙니다.** 실제로 이런 일이 있었습니다 — 서버에 녹음 파일이 있는데
요청서가 그걸 "요청하면 줄 수 있는 것"으로 적어 놨더니, Codex가 `find`로 목록만 확인하고
**열지도 않은 채 "자료를 더 주세요"로 끝냈습니다.** 그 파일이 결국 답을 담고 있었습니다.

이제는 이렇습니다.
- **원본 경로가 먼저**, 가설은 뒤에 짧게
- "요청하면 줄 수 있는 것"이 아니라 **"지금 열 수 있는 것"** 으로 적습니다
- `ls`·`find`로 목록만 본 것은 **연 것으로 치지 않습니다** (실행 기록으로 대조합니다)

⚠️ **귀·눈으로 확인한 증상은 Claude가 물어봅니다.** 소리 끊김·화면 깜빡임·체감 빈도 같은 건
코드에도 로그에도 없고 **사람만 압니다.** 그게 빠지면 분석이 반쪽이 됩니다.
반대로 빌드 실패나 컴파일 에러에는 묻지 않습니다 — 전부 파일에 있으니까요.

리뷰 범위는 알아서 잡습니다 — **커밋 안 한 게 있으면 그것을, 깨끗하면 기본 브랜치와 비교.**
따로 정하고 싶으면 말하면 됩니다: "main 기준으로 리뷰해" · "이 커밋만 리뷰해"

> 💡 **요청은 작게 주는 게 훨씬 빠릅니다.** 각각 한 번씩 잰 두 사례입니다 —
> 커밋 안 된 변경 전체를 리뷰시키면 Codex가 파일마다 명령을 돌려 **20분**이 걸렸고,
> 판단이 필요한 코드만 요청서에 담아 물었더니 **1분 25초**에 끝났습니다(명령 36건 → 4건).
> 급할 때는 "이 함수만 봐줘"처럼 좁혀서 물으십시오.

## 4. 결과는 파일로 남습니다

프로젝트의 **`docs/codex_rescue/`** 에 쌓입니다.

```
260817_210036_review_auth-refactor.md        ← 코드 리뷰 결과
260817_182041_request_fcm-token-null.md      ← Claude가 쓴 요청서
260817_182041_response_fcm-token-null.md     ← Codex 답변 + Claude 검토 (되묻기 턴도 여기 쌓임)
260817_182041_followup2_fcm-token-null.md    ← 되묻기 반박서 (2026-08-25 신설)
.log/260817_182041_events.jsonl              ← 실행 중 실시간 기록 (진행 패널이 읽는 것)
.scratch/                                    ← Codex의 작업 폴더 (2026-08-25 신설)
```

**`.scratch/` 는 Codex가 조사하며 만든 것들입니다** — 계산 스크립트, 중간 데이터, 파싱 결과.
예전에는 임시 파일조차 금지였는데, 그러면 파형 정렬이나 로그 재집계 같은 **파일이 필요한 계산을
아예 시작하지 못합니다.** 그게 분석이 겉돌던 이유 중 하나였습니다.
여기 남은 것은 **위반이 아니라 조사의 흔적**이고, 응답의 수치가 어떻게 나왔는지 따질 때 열어 봅니다.
`.log/` 와 마찬가지로 git에서 자동 제외됩니다.

**Codex 원문은 손대지 않고 Claude 검토를 아래에 덧붙입니다.**
나중에 "Codex가 실제로 뭐라 했나"를 잃지 않습니다. **커밋해서 남기라고 만든 기록**이며,
커밋해 두면 다음 세션이 그대로 이어받습니다. 스킬이 대신 커밋해 주지는 않습니다.

**`.log/` 는 스킬이 자동으로 git에서 제외합니다** — 디렉토리를 만들 때 그 안에 `.gitignore`
(내용 `*`)를 함께 떨굽니다. 명령 출력·MCP 인자·에이전트 메시지 전문이 담겨 유출 위험이 있고
크기도 크기 때문입니다(한 번 실행에 105줄 / 409KB 측정). 요청서·응답 md는 한 단계 위에 있어
영향받지 않고 그대로 커밋됩니다.

### 쌓이는 양과 정리

쌓이는 양은 **실행 성격에 따라 크게 다릅니다.** 남아 있는 측정값은 이렇습니다 — 어떤 실행은
105줄 / 409KB였고, 다른 표본들은 이벤트 파일만 394~750KB였습니다. 한 464KB 표본에서는 86%가
명령 실행 결과 전문이었습니다. 평균이 아니라 **표본**으로 읽으십시오.
**기본은 영구 보관이며 아무것도 자동으로 지워지지 않습니다.**

claudeStateBar 확장을 쓰신다면 두 가지 방법이 있습니다.

- **수동** — 진행 패널의 카드에서 🗑. **묻지 않고 문서까지 통째로 휴지통으로** 보냅니다.
  꺼내려면 패널 상단의 🗑를 엽니다. 끝난 실행에만 버튼이 나타납니다.
  기록만 지울지 문서까지 지울지는 **휴지통에서 완전 삭제할 때** 고릅니다. 문서를 남기면
  그 문서만 남고, 그 실행은 `문서만` 카드로 계속 보입니다
- **자동** — 설정에서 `claudeContextBar.codexRunAutoCleanup` 을 켜면 확장이 시작될 때 1회
  정리합니다. 보관 기간은 `claudeContextBar.codexRunRetentionDays`(기본 7일), 문서까지 지울지는
  `claudeContextBar.codexRunDeleteDocs`(기본 끔)로 정합니다. 진행 중이거나 lock이 남은 실행은
  절대 건드리지 않습니다

## 5. 진행 상황을 눈으로 봅니다 (claudeStateBar 확장)

예전에는 Codex가 도는 몇 분 동안 무엇을 하는지 전혀 보이지 않았습니다.
이제 확장이 **실행 중인 활동을 실시간으로** 보여줍니다.

**여는 법** — 상태바 클릭 → `Codex 실행 N건`, 또는 `Ctrl+Shift+P` → `claudeStateBar: Show Codex Runs`

보이는 것:

| | |
|---|---|
| **말 / 생각** | Codex가 "이제 뭘 하겠다"고 말한 문장 — 가장 쓸모 있는 정보입니다 |
| **명령** | 실행한 명령과 종료 코드 |
| **검색 · 파일 · MCP** | 웹 검색어, 건드린 파일, 도구 호출 |
| **계획** | Codex가 계획을 세운 경우에만 `2/5` 형태로 |
| **알림** | CLI 안내 메시지 — **오류가 아닙니다** |

상태는 `시작 중 → 진행 중 → 마무리 중 → 완료 / 실패 / 중단 / 응답 없음` 으로 바뀝니다.

- **마무리 중**이 따로 있는 이유: Codex의 턴이 끝나도 스킬은 변경 검사·응답 회수·로그 보존을
  더 합니다. 그 구간을 "완료"로 표시하면 아직 안 끝난 걸 끝났다고 하는 셈입니다.
- **응답 없음**은 프로세스가 강제 종료된 정황입니다. 완료로 승격하지 않습니다.
  판정 근거는 **heartbeat 파일이 30초 넘게 갱신되지 않은 것**이며, 프로세스를 직접 조회하지는
  않습니다. 절전이나 파일시스템 지연으로도 이 상태가 나올 수 있습니다.
- **완료음**은 확장이 **진행 중인 상태부터 지켜본** 실행이 끝날 때만 울립니다
  (설정: `claudeContextBar.workflowCompleteBeep`). 확장을 켜기 전에 이미 끝나 있던 실행은
  조용히 목록에만 올라오고, `응답 없음`도 완료가 아니라 울리지 않습니다.
- **잘려서 다 안 보이는 줄은 클릭하면 그 자리에서 펼쳐집니다** (확장 1.9.3 이상). 한 번에 한 줄만
  열립니다. 다만 보이는 건 패널이 보관한 만큼입니다 — 말·생각은 4,000자, 명령은 600자까지.
  그보다 길면 `.log/<스탬프>_events.jsonl` 원본을 봐야 합니다.
- 패널은 워크스페이스 폴더마다 **최신 20건**까지만 보여줍니다. 그보다 오래된 실행은 파일로는
  남아 있고 자동 정리 대상도 되지만 목록에는 안 나옵니다.
- **기록 없이 문서만 있는 실행**도 `문서만` 표시가 붙은 카드로 나옵니다. 활동 목록은 없지만
  (그릴 기록이 없으니) 요청서·응답은 그대로 열립니다. 원시 기록을 지운 실행, 그리고 동료가
  커밋한 문서를 git으로 받아온 경우가 여기 해당합니다. 실행 모드(`READONLY` 같은 표시)는
  붙지 않습니다 — 그 값은 지워진 상태 파일에 있었고, 지어내지 않습니다.

**Remote-SSH로 연 워크스페이스에서도 보입니다** — 서버에서 돌린 실행이 그대로 목록에 뜹니다.
확장 **1.9.2 이상**이 필요합니다. **확장 자체는 서버에 깔지 않아도 됩니다** — 로컬에서 돌면서
원격 파일을 읽습니다. 다만 **서버에서 실행을 시작하려면 그 서버에 Codex CLI와 이 스킬이 있어야
합니다**(§0의 요구사항 그대로). 원격에서는 활동 목록만 최대 5초 간격으로 갱신됩니다(상태와
완료음은 그대로 2초). 원격 파일은 구간 읽기가 안 돼 진행 중인 실행의 기록을 통째로 가져와야
하기 때문입니다.

⚠️ **진행률(%)은 표시하지 않습니다.** Codex는 앞으로 도구를 몇 번 부를지 미리 알리지 않기 때문에
전체 진행률은 원리적으로 계산할 수 없습니다. 대신 경과 시간과 활동 수를 보여줍니다.

### 되묻기를 하면 (2026-08-25)

**같은 카드가 되살아납니다.** 되묻기는 원래 실행과 같은 스탬프를 쓰고 기록을 이어 붙이므로,
확장이 그것을 "다시 돌았다"로 보고 굳어 있던 카드를 되살립니다. 모드 표시는 `FOLLOWUP` 으로 바뀝니다.

⚠️ **다만 활동 목록은 아직 온전하지 않습니다.** `codex exec resume` 은 턴이 바뀔 때마다 활동
번호를 `item_0` 부터 다시 매기는데, 확장의 파서는 그 번호로 항목을 찾아 덮어씁니다. 그래서 앞 턴의
활동 중 번호가 겹치는 것들이 뒤 턴 것으로 바뀝니다. 실측한 2턴 왕복에서는 활동 20개(1턴 12개 +
2턴 8개) 중 화면에 12개만 남았고, 같은 번호를 받은 한 항목은 1턴의 `파일 변경`이 2턴의
`명령 실행`으로 종류까지 바뀌어 있었습니다. 번호가 겹치지 않는 항목은 그대로 살아남기 때문에
무엇이 사라지는지도 일정하지 않습니다. 상태가 `마무리 중`에서 안 내려오는 것도 같은 자리의
문제입니다 — 앞 턴의 종료 신호가 뒤 턴이 시작돼도 지워지지 않습니다.

**확인된 문제이며 수정 작업이 진행 중입니다.** 어긋나는 건 카드에 그려지는 활동 목록뿐이고,
요청서·응답 문서와 대화 내용 자체는 영향받지 않습니다. 정확한 기록이 필요하면
`.log/<스탬프>_events.jsonl` 원본을 보십시오 — 거기에는 두 턴이 모두 남아 있습니다.

⚠️ **삭제도 아직 온전하지 않습니다** — 카드에서 🗑 로 지울 때 **반박서(`_followup<N>_`)와
턴별 기록(`_t<N>_`)이 남습니다.** 위 항목과 함께 `docs/CODEX_RESCUE_MULTITURN_IMPACT.md` 에
정리해 뒀습니다. 그때까지는 그 파일들을 손으로 지우셔야 합니다.

## 6. Codex는 마음대로 못 고칩니다

"수정시켜"가 아니면 **프로덕션 코드를 건드리지 않습니다.** 말로만 막는 게 아닙니다 —
실행 전후 파일을 **실측 비교**해서, 정상 산출물 말고 뭐가 바뀌었으면 보고합니다.

발견해도 **알아서 되돌리지 않습니다.** 되돌릴지 살릴지는 사용자가 정합니다.

🔴 **2026-08-25에 경계선을 다시 그었습니다.** 예전에는 "쓸 수 있는 파일은 응답 문서 하나뿐"
이었고 **임시 파일조차 금지**였습니다. 그런데 실측해 보니 샌드박스는 이미 디스크 읽기와
임시 폴더 쓰기를 허용하고 있었습니다 — **막고 있던 건 권한이 아니라 프롬프트였습니다.**
그 결과 Codex는 계산에 파일이 필요한 조사를 시작조차 못 하고 추론만 하다 결론에 못 갔습니다.

이제 경계선은 **하나**입니다.

| | |
|---|---|
| ❌ **막는 것** | 프로덕션 파일 수정 — 소스·설정·데이터. git 상태를 바꾸는 명령도 |
| ✅ **푸는 것** | 디스크 읽기 · 계산·스크립트 실행 · `.scratch/` 쓰기 · 네트워크 **조회** |

네트워크는 문서·이슈·릴리스노트를 직접 확인하라고 열었습니다. **조회 전용**이며 업로드는 금지입니다.
끄고 싶으면 `CR_NETWORK=false` 입니다.

`.scratch/` 에 파일이 생겨도 **위반 경보가 아니라 `🧪 조사 흔적`으로 따로 보고**됩니다.

**"수정시켜"라고 해도 바로 안 고칩니다.** 승인 전에는 **스크립트가 거부합니다.**
예전에는 Claude가 "진행할까요?" 묻는 게 약속일 뿐이라 잊으면 그냥 고쳐졌습니다. 지금은 코드가 막습니다.

### 변경 감지가 못 잡는 것

"응답 파일 외 변경 없음"은 **"감시 범위에서 최종 상태 차이가 없었다"**는 뜻입니다. 다음은 통과합니다.

- 제외 영역 내부 — `.git` · `node_modules` · `build` · `.gradle` · `.dart_tool` · `.venv` · `.next` · `__pycache__`
- 생성 후 삭제, 기존 파일의 mtime 원복
- 실행 종료 후 자식 프로세스가 만든 지연 변경
- **원인 귀속 불가** — 다른 프로세스나 동기화 도구의 변경과 구별할 수 없습니다

🔴 **감시는 프로젝트 폴더 안에서만 유효합니다.** 그래서 `CR_SANDBOX=danger-full-access` 는
쓰지 않습니다 — 그 모드에서는 폴더 밖 수정을 **원리적으로 못 보면서** "변경 없음"을 출력합니다.
감시자가 눈을 감고 안전하다고 말하는 셈이라, 굳이 쓰면 보고에 경고가 붙습니다.

더 엄격하게 막으려면 `CR_SANDBOX=read-only`를 쓰십시오. Codex에게 쓰기 권한을 아예 주지 않고,
최종 메시지를 스크립트가 응답 파일로 저장합니다.
⚠️ 단 이 값은 **`.scratch/` 도 함께 막습니다.** 조사가 추론으로 제한되니 평상시에는 권하지 않습니다.

## 7. 함정

- **리뷰는 git 레포에서만 됩니다.** 아니면 "분석해줘"로 물으십시오
- **리뷰 지적을 다 고치지 마십시오.** 오탐과 취향 문제가 섞입니다. 골라서 적용합니다
- **범위와 집중 지시를 같이 못 줍니다** (Codex CLI 제약)
  "main 기준으로 인증 위주로 리뷰해"처럼 둘을 같이 주면 범위가 덜 정확하게 들어갑니다.
  **범위가 중요하면 집중 지시 없이** 시키는 게 낫습니다
- **답이 왔다고 다 성공은 아닙니다** — Codex가 "파일을 못 읽었다"고 답하는 경우가 있습니다.
  Claude가 내용까지 확인하지만, 답이 이상하면 로그를 보라고 하면 됩니다
- **`error` 로 표시되는 게 다 오류는 아닙니다** — CLI 안내 메시지가 같은 채널로 옵니다.
  패널에서는 `알림`(노란 점)으로 구분해 보여줍니다

## 8. 안 될 때

| 증상 | 원인 · 해결 |
|---|---|
| "git 레포가 아니다" | 리뷰는 git 전용. **"분석해줘"로 바꿔** 물으면 됩니다 |
| "리뷰할 변경이 없다" | 커밋을 다 했고 기본 브랜치면 볼 게 없습니다. `이 커밋만 리뷰해`처럼 대상을 주십시오 |
| **Codex가 파일을 못 읽는다** | Windows 샌드박스 계정 문제(에러 1332). 스킬이 `windows.sandbox=unelevated`로 우회합니다. 그래도 안 되면 `~/.codex/config.toml`을 확인하십시오 |
| 답이 이전 것과 똑같다 | 응답 파일 내용이 이번 실행에서 갱신되지 않은 것입니다. `send.sh`가 실행 전후 해시를 대조해 `stale`로 잡아 알려줍니다 |
| **"이미 실행 중"이라고 거부된다** | 같은 걸 두 번 동시에 돌린 것입니다. 먼저 것이 끝나길 기다리십시오 (파일 덮어쓰기 방지) |
| 패널에 아무것도 안 보인다 | 그 워크스페이스에서 아직 한 번도 실행하지 않은 것입니다. 한 번 돌리면 나타납니다 |
| **원격 워크스페이스인데 비어 있다** | 확장이 1.9.2 미만이면 그게 원인입니다(그 전 버전은 원격 파일을 못 읽었습니다). 1.9.3인데도 비면 원격 쪽 `docs/codex_rescue/.log/`에 `*_events.jsonl`이 있는지, 읽을 권한이 있는지 확인하십시오 |
| 진행이 실시간으로 안 보인다 | 스킬이 구버전일 수 있습니다. 실시간 기록은 나중에 추가된 기능이니 §0으로 다시 받으십시오 |
| `CR_TIMEOUT` 을 쓰니 거부당한다 | 제거된 변수입니다. Windows에서 동작하지 않는 것이 실측으로 확인돼 막아 두었습니다 |

## 9. 환경변수

| 변수 | 용도 |
|---|---|
| `CR_MODEL=<모델>` | Codex 모델 지정 |
| `CR_SANDBOX=read-only` | Codex에게 쓰기 권한을 주지 않음 (가장 안전) |
| `CR_ALLOW_EDIT=1` | 수정 모드 해금 — **승인 후에만** |
| `CR_DRYRUN=1` | Codex를 실행하지 않고 조립된 명령만 출력. 단 로그·작업 디렉터리와 그 안의 `.gitignore`는 미리 만들어질 수 있습니다 |
| `CR_WIN_SANDBOX=<모드>` | Windows 샌드박스 구현 방식. 기본 `unelevated` (에러 1332 회피용). 빈 값으로 두면 `config.toml` 설정을 그대로 씁니다 |
| `CR_NETWORK=false` | 네트워크 차단 (기본은 **허용**, 조회 전용) — 2026-08-25 신설 |
| `CR_CONSULT_MAX_TURN=<n>` | 되묻기 턴 상한. 기본 **11** — 사용자가 직접 대화로 결론에 도달한 실측 턴 수입니다 |
| `CR_CHAT_LIMIT=<초>` | 핑퐁 시간 상한. 기본 **60** (예전 120). 탐색을 열려면 이 값을 **함께 명시**해야 합니다 |
| `CR_CHAT_LOOK_MAX=<바이트>` | 핑퐁에 실어 보낼 자료의 총 크기 상한. 기본 65536 |
