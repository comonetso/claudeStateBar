### 1-2. 조사 경위와 결과
코드 조사로 아래 두 갈래를 확인했다.

**(1) 한도를 어디서 읽나** — `claudeContextBar` 는 이미 두 경로로 Codex 계정 한도를 읽고 있었다.
- [src/providers/codex/usageProvider.ts:190](../../src/providers/codex/usageProvider.ts#L190) `fetchCodexRateLimits()` — `codex app-server` 를 spawn 해서 `account/rateLimits/read` RPC 호출. 실측 774ms.
- 확장이 60초 주기로 갱신하는 캐시 파일 `%APPDATA%\Code\User\globalStorage\blueming.claude-state-bar\codex-account-usage-v1.json` — 단 **로컬 PC 전용**(확장이 로컬에서만 돎, 서버에는 없음).
- 직접 `codex app-server` 를 실측 프로브해서 응답 스키마 전체를 받았다(마스킹 처리). `rateLimits.primary/secondary.usedPercent`, `resetsAt`(epoch초), `planType`, `credits`, `rateLimitReachedType` 등.

**(2) 한도 초과 시 왜 결과가 통째로 날아가나** — `~/.claude/skills/codex_rescue/scripts/live-consult.mjs` 를 읽어 확인.
- Codex 는 응답 문서를 **조사가 끝난 시점에 한 번**만 쓴다(최근 실사례 2건 다 마지막 `agentMessage` 에 전체 응답이 들어 있었음).
- 중계기(`live-consult.mjs:741`)는 `item/completed` 알림 중 마지막 단계(`FINALIZE_PHASE`) 메시지 하나만 `finalText` 로 잡는다. 중간 메시지는 버려진다.
- 한도 초과로 턴이 `failed` 로 끝나면 `finalText` 가 비고, `send.sh` 는 "응답 없음"으로 종료한다.
- 응답 문서가 없으면 `thread_id` 도 안 남아(`send.sh:1920` 부근 — 응답 문서에만 frontmatter 를 심음) 리셋 후에도 같은 대화를 이어갈 수 없다.
- `codex app-server generate-json-schema` 로 실제 스키마를 뽑아 확인: `RateLimitReachedType` enum 에 `usageLimitExceeded` 계열 값이 있고, `TurnStatus` 에 `failed` 가 있다. **단 실제로 이 경로를 탄 로그 사례는 찾지 못했다** — 최근 3주 rollout 을 grep 했지만 한도 초과로 실패한 턴을 발견 못 함.

### 1-3. 비용 실측
최근 3주 Codex rollout 에서 CONSULT 계열 실행 11건의 5시간 창 사용률 변화를 스크립트로 집계(`rl_cost.mjs`, 스크래치패드에만 있음, 커밋 안 함): 1회당 +2%~+50%, 중간값 약 +21%. 09-09 CrewPhone 건은 52%→96% 로 끝나 "한 번 더 돌렸으면 끊겼을" 상황이었다.
