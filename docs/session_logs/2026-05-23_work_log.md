## 1. 작업 흐름 (시간순)

### 1-1. 컴팩트 모드에서 claudeState 플랜 표시 축약
**배경**: 컴팩트 모드는 공간 절약이 목적인데, 플랜 suffix가 `세션한도 3% (4시간 24분 후)` 로 길게 표시됨
**요구사항**: 컴팩트 모드 시 `3% (4h 24m)` 형식으로 축약
**처리**:
- `untilHumanCompact()` 함수 신규 추가 — 언어 중립적 `4h 24m` / `2d 3h` / `45m` 포맷
- `planTextSuffix(compact: boolean)` 파라미터 추가
  - 비컴팩트: ` - 세션한도 3% (4시간 24분 후)` (기존 유지)
  - 컴팩트: ` · 3% (4h 24m)` (· 구분자는 idle suffix와 동일 스타일)
- 호출부(1100번 라인)에 `compactMode` 전달
**결과**: 컴파일 통과

### 1-2. 툴팁 주간 Total/Sonnet 분리 표시 + 리셋 시각 추가
**배경**: 마우스오버 툴팁에서 Sonnet이 `🧩 Sonnet: 6%` 로만 표시 — 리셋 날짜 없고 주간 한도임이 불명확
**요구사항**: `주간 Total: 24% — 토 3:00 (3시간 0분 후)` / `주간 Sonnet: 6% — 토 3:00 (3시간 0분 후)` 형식
**처리**: `planTooltipBlock()` 수정
- 주간 Total 라인: `resetAtLabel` 뒤 `untilHuman` 추가 (기존에 누락)
- Sonnet/Opus: 한 줄 몰아넣기 → 각 모델별 개별 라인, 동일 `weeklyResetAt` 기준 리셋 시각 표시
- Opus는 null이면 여전히 숨김
**결과**: 컴파일 통과

### 1-3. 비활성(hideAfter 초과) 시 가장 최근 세션 fallback 표시
**배경**: 오랫동안 활동 없으면 claudeContext 아이템이 아예 사라짐 — 사용자가 마지막 세션 상태를 볼 수 없음
**처리**: `findActiveSessions()` 수정
- `fallbackCandidate` 지역 변수 추가 — hideThreshold 무관하게 가장 최근 파일 추적
- 파일 스캔 시 scope 필터 통과한 모든 프로젝트에서 newest 파일을 `fallbackCandidate`로 갱신
- 반환 직전 `visibleSessions.length === 0` 이면 fallbackCandidate로 세션 1개 생성 (`isIdle: true`, `isFallback: true`)
**결과**: 컴파일 통과

### 1-4. claudeState dim 분리 — fallback 세션과 독립 표시
**배경**: 1-3에서 fallback 세션이 `isIdle: true` → 상태바 아이템 전체가 회색. 같은 아이템에 merge된 claudeState 텍스트도 회색으로 보임. claudeState는 실시간 플랜 정보라 항상 선명해야 함
**처리**:
- `SessionInfo`에 `isFallback?: boolean` 필드 추가
- `planAdd` 계산 시 `isFallback`이면 '' (merge 안 함)
- `updatePlanFallback()` 호출 조건: `!sessions.some(s => !s.isFallback)` — 실제 세션이 없을 때만 planFallbackItem 활성화
- `updatePlanFallback()` 내부에 `compactMode` 분기 추가: 비컴팩트 → `세션 6% 주간 25%` / 컴팩트 → `S 6% W 25%`
**결과**: 컴파일 통과

## 3. 시행착오 / 사이드퀘스트 ★

- **실시간 thinking 표시 검토**: 사용자가 CLI의 `12s • ↓731 tokens • still thinking` 같은 표시를 VS Code 상태바에서 보고 싶다고 요청. JSONL 구조 분석 결과 JSONL은 각 단계 완료 후에만 기록 → 실시간 스트리밍 데이터 접근 불가 확인. 결론: thinking 소요 시간(완료 후)은 가능, 실시간 카운트는 불가. CLI는 API를 직접 호출하는 1인칭이라 가능한 것.

---

## 4. 발견한 코드베이스 함정 ★

- **planFallbackItem 표시 조건**: `noSessions`(sessions.length === 0)로만 판단하면 fallback 세션이 포함될 때 planFallbackItem이 숨겨짐 → claudeState가 dim 세션에 merge되어 같이 흐려짐. `sessions.some(s => !s.isFallback)`으로 실제 세션 유무를 별도 판단해야 함.
- **`const` 배열에 `.push()` 가능**: `const visibleSessions = finalSessions.filter(...)` 로 선언된 배열에도 `.push()` 는 가능 (재할당만 금지). fallback 세션 추가 시 활용.

## 5. 사용자 핵심 발언 박제 ★

- > "컨텍스트야 오랫동안 활동이 없으면 흐리게 보이는게 맞지만, state는 그렇지 않잖아"
  - 맥락: fallback 세션 추가 후 claudeState도 같이 dim으로 보이는 문제 지적
  - 적용: claudeContext(세션 기반)와 claudeState(플랜 기반)는 독립된 생명주기. 세션 활동 여부가 플랜 표시 색상에 영향주면 안 됨.
