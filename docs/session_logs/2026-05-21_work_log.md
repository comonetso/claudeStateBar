## 1. 작업 흐름 (시간순)

### 1-1. Electron claudeState 앱 분석
**배경**: 사용자가 별도 Electron 앱 `F:\workspace\Etc Project\Electron Project\claudeState`(Claude.ai 플랜 사용량 위젯)를 윈도우 앱으로 따로 띄우는 게 낭비라며, 이 VS Code 확장에 통합 요청
**처리**: Explore 에이전트로 전체 구조 정독. 핵심: `api.js`(claude.ai usage API), `telegram.js`(세션리셋 알림), `storage.js`(safeStorage 암호화), `settings/`(UI), `i18n/`(ko·en)
**결과**: 이식 대상 확정

### 1-2. 통합 방식 설계 (Webview)
**요구사항**: 설정에서 한/영 언어 토글(기본 영어), 모든 텍스트 한글화, sessionKey/Org ID/Bot Token을 설정 최상단, 언어토글 최상단
**처리**: VS Code 표준 설정 화면은 런타임 언어토글 불가 → Webview 패널로 결정. Context 설정 + claudeState 설정을 하나의 Webview에 통합. 표준 설정 화면도 유지(settings.json 동기화)
**결과**: 방식 B(Webview) 확정

### 1-3. 핵심 로직 이식 (신규 모듈 4개)
**처리**:
- `src/i18n.ts` — ko/en 딕셔너리 + t(). claudeContextBar 설정 라벨까지 포함
- `src/credentials.ts` — sessionKey/botToken/chatId는 `context.secrets`(암호화), orgId/interval/language는 config, lastSessionResetAt는 globalState
- `src/planUsage.ts` — claude.ai API. Electron `net.request` → Node `https.request` 변환
- `src/telegram.ts` — sendMessage/resolveFirstChatId/testToken (순수 https라 거의 그대로)
**결과**: 컴파일 통과

### 1-4. Webview 패널 구현
**처리**: `src/settingsPanel.ts`(CSP/nonce, 메시지 통신, 저장) + `media/settings.html(인라인)`·`settings.css`(VS Code 테마변수)·`settings.js`(acquireVsCodeApi)
**결과**: 컴파일·패키징 성공, media 포함 확인

### 1-5. extension.ts 통합
**처리**: 폴링·상태바·세션리셋감지·메뉴 연결. 커맨드 2개(openSettings, refreshPlanUsage). configWatcher에 claudeState 추가
**결과**: 컴파일 통과

### 1-6. 상태바 표시 방식 통합 (사용자 재설계)
**배경**: 사용자가 S/W 별도 아이템 대신 세션 아이템 한 줄에 합치길 원함
**처리**: S/W 별도 아이템 제거 → 첫 세션 아이템에 플랜 세션% suffix 합침(`- 세션한도 44% (2시간 2분 후)`). 주간은 툴팁. 툴팁의 firstMessage/projectPath 제거 → 플랜 State 블록 삽입. 세션 없을 때 fallback 단독 아이템
**결과**: 컴파일·패키징 성공

### 1-7. ★ Cloudflare 우회 (핵심 트러블슈팅)
**배경**: 사용자가 sessionKey 입력했는데 "만료" 표시. "일렉트론에서는 졸라 잘 먹어"
**원인 분석**: 진단 스크립트로 확인 → Node `https`로 claude.ai 요청 시 **HTTP 403 + server:cloudflare + "Just a moment..." 챌린지**. 키 만료가 아니라 Cloudflare가 Node의 TLS 핑거프린트를 봇으로 차단. 우리 코드가 403을 auth_expired로 오해
**처리**: `planUsage.ts`에 `require('electron').net` 우선 사용 + https 폴백. Electron net은 Chromium 네트워크 스택이라 TLS 핑거프린트가 Chrome과 동일 → Cloudflare 통과. `getTransport()` 진단 export + 로그 추가
**결과**: ✅ 실기기에서 session=44%, weekly=17%, Sonnet 4% 정상 표시 확인. transport=electron 통과 검증됨

### 1-8. enabled 토글 제거
**배경**: 사용자 "없으면 안 보여주는 게 아니고 경고를 해야지"
**처리**: `claudeState.enabled` 설정 제거. 자격증명 유무로만 판단. 미설정/만료/에러 시 색깔 배경(warning/error) 경고 아이템 항상 표시
**결과**: 컴파일 통과

### 1-9. 표시이름 claudeStateBar 전면 통일
**배경**: 사용자 "claudeStateBar로 졸라 통일"
**처리**: displayName, README 제목, Webview 탭/제목, 커맨드 팔레트 prefix, 설정 카테고리, Output 채널명 전부 `Claude Context Bar`/`claudeState` → `claudeStateBar`. "주간 전체"→"주간". 44%에 "세션한도" 라벨
**결과**: 컴파일·패키징 성공. 단 식별자(ezoosk.claude-context-bar)·설정키(claudeContextBar.*)는 호환 위해 유지

## 3. 시행착오 / 사이드퀘스트 ★

- **잘못된 가정**: sessionKey "만료" 메시지를 보고 키 문제로 의심할 뻔
- **어떻게 발견했나**: 진단 스크립트(`node`로 claude.ai 직접 요청)로 403 + cloudflare + "Just a moment..." 본문 확인
- **복구 방법**: electron.net 폴백 추가
- **교훈**: claude.ai 비공식 API 403은 "인증 만료"가 아니라 **Cloudflare 봇 차단**일 수 있다. Node https는 막히고 Electron net(Chromium 스택)은 통과한다

---

## 4. 발견한 코드베이스 함정 ★

- **claude.ai + Cloudflare**: Node `https.request`는 TLS 핑거프린트 때문에 403(Just a moment) 차단됨. VS Code 확장 호스트는 Electron 기반이라 `require('electron').net`으로 Chromium 스택 사용 가능 → Cloudflare 통과. `planUsage.ts`가 electron 우선 + https 폴백
- **claude.ai usage 응답 구조**: `{ five_hour:{utilization,resets_at}, seven_day:{...}, seven_day_sonnet:{...}, seven_day_opus:null|{...} }`. utilization이 % (사용률)
- **세션 리셋 감지**: 이전 resets_at이 이미 지났고 + 새 resets_at과 다를 때만 리셋으로 판정 (false positive 방지)
- **VS Code 상태바 제약**: 멀티라인·프로그레스바 불가. 텍스트+$(icon)+색상1개+hover툴팁(멀티라인 가능)만
- **displayName vs 식별자**: displayName 변경은 안전, 식별자/publisher 변경은 마켓에서 별개 확장이 됨
