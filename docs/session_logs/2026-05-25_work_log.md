## 1. 작업 흐름 (시간순)

### 1-1. completionBeepSettleMs 범위 조정
**배경**: 사용자가 settle 값을 5000으로 저장하고 싶었으나 이전 max=10000 범위에서 UI가 혼란스러움  
**요구사항**: 100~5000ms 범위로 변경 (step=100)  
**처리**:
- [package.json](../../package.json): `minimum: 0 → 100`, `maximum: 10000 → 5000`, description 업데이트
- [src/settingsPanel.ts](../../src/settingsPanel.ts): `clampSettle` → `Math.max(100, Math.min(5000, ...))`
- [src/settingsPanel.ts](../../src/settingsPanel.ts): HTML input `min="0" max="10000" step="500"` → `min="100" max="5000" step="100"`
- [media/settings.js](../../media/settings.js): fallback `|| 0` → `|| 1000`  
**결과**: 컴파일 통과, vsix 빌드 완료 (1.7.3)

### 1-2. 저장 안 됨 오진단 → 수정
**배경**: 사용자가 5000 게인 저장 후 패널 닫았다 열면 300으로 돌아온다고 보고  
**소넷 오진단**: `findstr`로 settings.json 검색 → 한글 코드페이지 불일치로 `claudeContextBar` 키 못 찾음 → "저장이 전혀 안 됨"으로 잘못 결론  
**옵스 재진단**: PowerShell `ConvertFrom-Json`으로 정확히 파싱 → 모든 claudeContextBar 설정이 정상 저장되어 있음 확인  
**실제 원인**: 사용자가 작업 완료 게인 칸(max=300 제한)에 5000을 입력 → clamp되어 300으로 저장됨. 사용자는 "원상복구"로 인식했지만 사실 max 제한에 의한 정상 동작  
**교훈**: Windows에서 `findstr`로 다국어 설정 파일 검색 시 코드페이지 문제 → PowerShell `ConvertFrom-Json` 필수

### 1-3. 게인 max 300 → 5000으로 확장
**배경**: 영상 시청 중 시스템 볼륨을 낮게 유지하면서 비프만 크게 듣고 싶은 사용자 요구  
**요구사항**: 4종 게인(경고/위험/완료/질문) 모두 50~5000% 허용  
**처리**:
- [package.json](../../package.json): 4개 gain 설정 `maximum: 300 → 5000`, description에 클리핑 경고 추가
- [src/settingsPanel.ts](../../src/settingsPanel.ts): `clampGain` → `Math.min(5000, ...)` (replace_all로 4개 input max 일괄 변경)
- [src/settingsPanel.ts](../../src/settingsPanel.ts): sound.hint fallback 텍스트 "50~300" → "50~5000, 300% 이상 클리핑 경고"
- [src/i18n.ts](../../src/i18n.ts): EN/KO `sound.hint` 업데이트 (50~5000 + 클리핑 경고)
- [media/settings.css](../../media/settings.css): `.sound-row` grid `72px → 84px` (4자리 숫자 수용)  
**결과**: 컴파일 통과, vsix 재빌드 완료

## 2. 의사결정 로그

| # | 결정 사항 | 근거 | 검토한 대안 | 트레이드오프 |
|---|---|---|---|---|
| 1 | settle min=100 (0 제거) | 0은 "즉시 발사" = debounce 없음, 오탐 복귀. 의미 없는 값 제거 | min=0 유지 | 기존 0으로 설정한 사용자 없으므로 파급 없음 |
| 2 | 게인 max=5000 허용 | 사용자 요청. WAV 조용한 파일은 300%도 안 깨질 수 있음 | max=1000 | 클리핑 책임은 사용자에게, hint로 경고 |
| 3 | settle 기본값 3000 유지 | 1000으로 줄이면 hook 자동 follow-up 오탐 재발 우려 | 1000ms | 사용자가 직접 설정 가능 |

## 3. 시행착오

- **잘못된 가정**: `findstr /i "claudeContextBar"` 로 settings.json 검색 가능하다고 전제
- **어떻게 발견했나**: 옵스가 PowerShell로 재확인 → 모든 키 정상 존재 확인
- **복구 방법**: `Get-Content | ConvertFrom-Json`으로 정확히 파싱
- **교훈**: Windows 다국어 환경에서 Bash `findstr`/`grep`으로 UTF-16 또는 BOM 있는 JSON 파일 검색 시 인코딩 불일치 → 반드시 PowerShell로 파싱

---

## 4. 코드베이스 함정

- `clampGain`과 `clampSettle`은 `settingsPanel.ts`의 `handleMessage` → `save` case 내에 인라인으로 정의되어 있음. 별도 유틸 함수 아님
- HTML input `max` 속성이 있어도 사용자가 키보드로 그 이상 입력 가능 (브라우저 form validation은 submit 시에만). 실제 제한은 `clampGain`/`clampSettle`이 담당
- Windows `%APPDATA%\Code\User\settings.json` 검색 시 `findstr`은 인코딩 문제로 실패할 수 있음. PowerShell `ConvertFrom-Json` 사용 필수
