## 1. 작업 흐름

### 1-1. Codex 계정 한도를 사용률로 반전

**배경/요구**: 사용자 "클로드는 토큰사용량을 표시하잖아, 코덱스도 토큰 사용량으로 바꿔야겠어.. 이게 헷갈리네".
조사해보니 앞쪽 `(23%)` 컨텍스트 사용률은 **양쪽이 이미 동일**했고, 실제 불일치는 뒤쪽 계정 한도였다.

| | 값 | 의미 |
|---|---|---|
| Claude | `sessionPercent` ([extension.ts:2622](../../src/extension.ts#L2622)) | **사용**률 |
| Codex | `codexRemainingPercent` (구) | **잔여**율 |

**처리**: `codexRemainingPercent` → `codexUsedPercent`로 교체하고 호출부 3곳(상태바 접미사·툴팁 primary/secondary·account-only 폴백) 정리.
레이블도 함께 바꿨다 — 값이 사용률인데 "남음"이라 적혀 있으면 그 자체가 거짓 표시다.
`sb.codexLimit` `Remaining`→`Weekly` / `남음`→`주간한도`, `sb.codexSecondary`에서 "remaining/남음" 제거.

**결과**: 컴파일 통과, 로컬 설치 후 사용자 확인.

### 1-2. "왜 코덱스만 주황색이지? 컨텍스트도 널널한데"

**배경**: 사용자 스크린샷 — `⬢ Cxi: gpt 5.6 sol - High (28%)`가 주황빛.

**처리**: 색 결정 경로를 따라가니 28%는 경고 임계값(50%) 아래라 마지막 갈래(`projectColorMap`)였다.
이름이 `CCB`(claudeContextBar)와 `Cxi`로 갈려 팔레트 0번(`#a8d8ea`)과 1번(`#d4a5a5` 더스티 로즈)을 각각 받은 것.
`Cxi`는 `getShortName("calltaxi")` → 단일 단어 → `C` + 마지막 음절 `xi`. 즉 **다른 프로젝트 세션이었다.**

**결과**: 경고색이 아니라 파스텔이라는 사실 확정. 이것이 1-4(autoColor 제거)의 직접 계기가 됐다.

### 1-3. 왜 다른 프로젝트 대화가 이 창에 떴나 — 로그 3단 대조

**배경**: 사용자 "아니왜 .. 다른 플젝이 표시되는지 알아야지.."

### 1-4. autoColor 제거 (기본값 변경 → 기능 제거로 확대)

**배경**: 사용자 "아이콘 색깔만 구분하고 글자색은 클로드하고 동일하게, 색상은 컨텍스트 경고 색상만 적용하기로".

**1차 처리(불충분)**: `autoColor` 기본값을 `true`→`false`로만 변경.
→ 사용자 `settings.json:162`에 `true`가 **명시**돼 있어 기본값이 무시됐다. 사용자: "글자색도 동일하게 변경되는데?"

**2차 처리(확정)**: 사용자 "자동색상 플젝별, 기능을 죽이는게 좋을듯" → 전면 제거.

| 위치 | 조치 |
|---|---|
| [extension.ts:1920](../../src/extension.ts#L1920) | 파스텔 9색 팔레트 + `projectColorMap` + `colorIndex` 삭제 → `restingColor` 단일 값 |
| 〃 `baseColorVariations` | 5단계 변주 배열 → `baseColorHex` 단일 색 맵 |
| package.json | `claudeContextBar.autoColor` 정의 삭제, `baseColor` description 재작성 |
| settingsPanel.ts | 체크박스 HTML + config read/update 제거 |
| **media/settings.js** | **`$('cb-autoColor').checked` 접근 2줄 제거** (§3-1 참조) |
| i18n.ts | `cb.autoColor.label` 삭제, `cb.baseColor.label`을 "세션 글자색"으로 |

**결과**: 색 변화는 idle / 경고 50% / 위험 75% 세 갈래만 남았다.

### 1-5. 타 프로젝트 Codex 대화 마커

**배경**: 사용자 "코덱스는 대화내역이 플젝단위가 아니고 디바이스 단위로 표시되어서 현재 플젝에서 다른 플젝의 대화가 열리거든. 그런데, 이건 정말 헷갈리는 부분이야."

**결과**: 컴파일 통과. **단 불일치 상태를 실제로 재현해 보지는 못했다**(HANDOFF 검증 미완 참조).

## 3. 시행착오

### 3-1. `media/settings.js`를 놓칠 뻔했다
- **잘못된 가정**: 설정 항목 제거는 `package.json` + `settingsPanel.ts`(HTML·config) 세 곳이면 끝난다.
- **발견 경위**: 제거 후 `grep autoColor src/ package.json`이 깨끗해 끝난 줄 알았다가, webview가 값을 어떻게 수집하는지 추적하다 `media/` 자산을 발견. `$('cb-autoColor').checked`가 **읽기·쓰기 두 곳**에 있었다.
- **복구**: 두 줄 삭제.
- **교훈 한 줄**: webview 설정 항목은 **TS 4곳 + 정적 JS 2곳**이다. TS만 지우면 컴파일은 통과하고 패널은 `null.checked`로 런타임에 죽는다 → [[vscode-webview-setting-removal]]

### 3-2. 기본값 변경으로는 사용자 설정을 못 이긴다
- **잘못된 가정**: `package.json`의 `default`를 `false`로 바꾸면 파스텔이 사라진다.
- **발견 경위**: 사용자 "글자색도 동일하게 변경되는데?" → `settings.json:162`에 `true`가 명시돼 있었다.
- **복구**: 기능 자체를 제거하는 방향으로 확대(사용자 지시).
- **교훈 한 줄**: 배포된 확장의 동작을 확실히 바꾸려면 기본값이 아니라 **설정 자체를 없애야** 한다. 기본값 변경은 "아직 안 건드린 사용자"에게만 닿는다.

### 3-3. "팝업 패널"이 무엇인지 몰라 전수 조사
- **잘못된 가정**: 사용자가 말한 "팝업 패널"이 설정 webview일 것이다.
- **발견 경위**: `grep`으로 settingsPanel·QuickPick 메뉴·워크플로우 패널을 모두 뒤졌으나 Codex 사용량 표시가 **하나도 없었다**. 실제 대상은 상태바 hover 툴팁이었고 이미 수정된 상태였다.
- **교훈 한 줄**: 화면 명칭이 모호할 때는 "그 숫자가 나오는 코드 위치"를 전수로 좁히면 후보가 저절로 하나가 된다.

## 5. 사용자 핵심 발언

- > "코덱스는 대화내역이 플젝단위가 아니고 디바이스 단위로 표시되어서 현재 플젝에서 다른 플젝의 대화가 열리거든. 그런데, 이건 정말 헷갈리는 부분이야."
  — 1-5 마커 기능의 출처. 도구가 "정직하게 표시"하는 것만으로는 부족하고, **사용자의 기대와 어긋나는 지점을 도구가 먼저 알려야** 한다는 요구.
- > "자동색상 플젝별, 기능을 죽이는게 좋을듯"
  — 기본값 off로 타협하지 않고 제거를 택한 근거. 적용 범위: 신호(색)가 두 가지 뜻을 가지면 둘 다 못 읽는다.
- > "아이콘 색깔만 구분하고 글자색은 클로드하고 동일하게 하기로 했는데,, 색상은 컨텍스트 경고 색상만 적용하기로"
  — 색 배분 원칙. 아이콘=정체성, 글자=상태. 향후 색을 추가할 때 이 경계를 넘지 말 것.
