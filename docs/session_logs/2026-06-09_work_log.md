**결정**: `ezoosk.claude-context-bar` → `blueming.claude-state-bar`. publisher=`blueming`, name=`claude-state-bar`, displayName=`Claude State Bar`.
**처리**: package.json의 publisher/name/displayName/repository/homepage/bugs URL 전부 교체.

**처리**: Fork notice를 최하단 Credits 한 줄로 내리고, Blueming 기능 중심으로 전면 재작성. 영/한 동기화.

**처리**: v1.0.0~v1.4.1 전부 삭제 → `[Before 1.5.0]` 한 줄 퉁침. v1.5.0부터 Blueming 스타일로 재작성.

### 1-5. package.json description 한글 → 영어 통일
**배경**: VS Code "기능" 탭에 한글이 섞여있어 혼란스럽다는 사용자 지적.

## 3. 시행착오 / 사이드퀘스트

- **잘못된 가정**: 사용자가 "1.7.2 버전으로" 요청 → "1.7.25"를 "1.7.2"로 변경. 사용자가 즉시 "1.7.25"로 정정. 교훈: 숫자 잘림 여부 확인 필요.
- **사용자 직접 설치 의도 무시**: settings 정리 후 사용자가 직접 설치하려 했는데 Claude가 먼저 설치. 사용자 "아니, 네가 왜 설치를 해?" → 제거 후 사용자 직접 설치. 교훈: "설치해"를 명시적으로 듣기 전까지는 빌드만 하고 대기.
- **마켓플레이스 "게시됨 날짜" 오해**: 사용자가 숨기려 함 → 서버 메타데이터라 불가 → 새 식별자로 올리면 새 날짜로 자동 해결됨.

## 4. 발견한 코드베이스 함정

- **VS Code settings.json은 확장 제거해도 유지됨**: `claudeContextBar.*` / `claudeState.*` 설정값이 확장 제거 후에도 settings.json에 잔류. 새 설치 테스트 시 반드시 수동 삭제 필요.
- **마켓플레이스 "기능" 탭**: package.json `contributes.configuration`의 description이 그대로 표시됨. 한글 혼재 시 혼란스럽게 보임.
- **⚙️ → "설정" 클릭 동작 오버라이드 불가**: VS Code API에서 기본 Settings Editor 열기를 커스텀 webview로 교체하는 방법 없음.
- **텔레그램 메시지는 i18n 적용됨**: `planT('tg.resetMsg')`로 언어 설정 따름. 한국어 설정 → 한글 메시지, 영어 설정 → 영어 메시지.
