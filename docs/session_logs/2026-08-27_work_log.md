## 1. 작업 흐름

### 1-1. 코덱스 알림 오발사 — `resetsAt` 1초 진동

**배경/요구**: 사용자가 "코덱스 텔레그램 발사가 시도때도 없이 되고, 리셋도 되지 않는다"고 지적.

**처리**: `%TEMP%\claudeStateBar-primer\` 의 이벤트 락 파일부터 봤다. 코덱스 락이 6개
(20:35·20:53·21:17·22:56·00:10·01:36 KST) — 5시간 주기여야 할 것이 18분~1시간 간격이었다.

`diag.log` 의 `← CLOSE EDGE` 6건을 뽑으니 갈렸다.

```
11:35:40  moved=18066000ms  ← 진짜 (약 5시간)
11:53:41  moved=1000ms      ← 가짜  used=2%
12:17:34  moved=1000ms      ← 가짜  used=10%
13:56:02  moved=1000ms      ← 가짜  used=48%
15:10:03  moved=1000ms      ← 가짜  used=48%
16:36:03  moved=18016000ms  ← 진짜 (약 5시간)
```

`resetsAt` 이 `…147000` ↔ `…148000` 을 오갔다. [extension.ts:3411](../../src/extension.ts#L3411) 의
`cur === prev` 정확 일치가 1초 흔들림을 "값이 움직였다 = 닫혔다"로 읽었다.

**결과**: `Math.abs(cur - prev) <= 5000` 으로 교체. 임계값 5초는 사용자 선택 —
실측 분포(진동 1초 / 닫힘 중 최소 전진 65초 / 진짜 종료 5시간) 사이에 아래 5배·위 13배 여유.

프라이머 검증([extension.ts:3495](../../src/extension.ts#L3495))도 `at === prevSeen` 정확 일치라
같은 진동에 당하는 자리였다. 함께 고쳤다.

### 1-2. 자동시작 불능 — 원격 홈이 로컬 프라이머로 샜다

**배경/요구**: 알림은 오는데 창이 안 열린다.

**처리**: `codex-primer-outcome` 이 2건뿐이었고 두 번째가 결정적이었다.

```
2026-08-26T11:36:15Z codex-primer-outcome=api-key-present
                     detail=could not read \root\.codex\auth.json (ENOENT)
```

Windows 로컬에서 `/root/.codex` 를 읽으려 했다. `primeNewCodexBlock()` 이
`getCodexHomeUri()` 의 `fsPath` 를 넘기는데, 이 함수는 **워크스페이스 기준**이라
Remote-SSH 창에서는 서버 홈을 돌려준다. 확장은 `extensionKind: ["ui"]` — 항상 로컬에서 돈다.

`codexBillingHazard()` 는 "못 읽으면 위험"이 설계였고,
`handleCodexPrimerOutcome()` 이 `setCodexAutoStartBlockOnReset(false)` 를 호출했다.
그 뒤 모든 `codex-block-closed` 가 `autoStart=false`. 설정 파일에도 박혀 있었다.

**결과**: 세 겹으로 막았다.
1. `codexBillingHazard()` 반환을 `{kind:'hazard'|'unreadable', reason}` 으로 구조화
2. `auth-unreadable` outcome 신설 — 이번 회차만 건너뛰고 설정은 안 건드림
3. `fireCodexPrimer()` 에서 **홈 인자 자체를 삭제** — 내부에서 `defaultCodexHome()` 호출

### 1-3. 데드락 — 닫힌 채 방치되면 영영 안 열린다

**배경/요구**: 설정을 되돌려도 창이 안 열렸다.

**처리**: 발사 조건이 `wasOpen && !isOpen` 인데 현재는 `wasOpen=N, isOpen=N`.
"닫히는 순간"이 이미 소비돼서 다시 오지 않는다. 창을 여는 게 프라이머고 프라이머는
그 순간에만 도니, 01:36에 닫힌 창이 05:55까지 **4시간 19분** 방치됐다.

**결과**: `codexClosedSince` 상태 신설. 닫힌 상태가 10분 지속되면 엣지 없이 발사.
사용자 결정 3건 — 10분 / 텔레그램 없음 / 10분마다 무한 재시도.

즉시 조치로 프라이머와 동일한 명령을 수동 실행해 창을 열었다(exit 0, `resetsAt` 고정 확인).

### 1-4. 클로드 04:00 리셋 — 서버 워밍 크론

**배경/요구**: 사용자가 "클로드가 서버에서 리셋되는 것 같다, 로컬이 절전인 04시쯤 리셋됐다".

**처리**: 절전 전후 폴링을 비교했다.

```
절전 직전 02:52 → 창 종료 예정 03:00, 사용률 7%
절전 복귀 05:36 → 창 종료 예정 09:00, 사용률 0%
```

09:00에 끝나는 창은 04:00에 시작된 창. 로컬은 02:56~05:35 절전(폴링 갭 159분 실측),
로컬 세션 파일도 그 구간에 0건. 로컬이 아니다.

서버 4대를 동시에 훑으니 **4대 전부 04:00에 세션 생성** + 동일 크론.

```
0 */4 * * * .../warm_token.sh
OUT="$(timeout 60 "${CLAUDE_BIN}" -p "한 단어로만: OK" --output-format json 2>&1)"
```

**결과**: 프라이머와 하는 일이 같다. 토큰 워밍이 목적인데 **부작용으로 5시간 창을 연다.**

### 1-5. 장수명 토큰 전환 + 워밍 크론 제거

**배경/요구**: 사용자 결정 — "4대 다 장수명 토큰 발행, 크론 제거. 창 여는 건 확장으로 충분.
로그아웃되면 내가 로그인한다." 이어서 "SportedAWS도 다시 갱신 — 4대가 같은 날 만료되게".

**처리**: `claude setup-token`(1년)을 사용자가 5대에서 실행,
`CLAUDE_CODE_OAUTH_TOKEN` 환경변수로 저장. 서버는 `.bashrc`, 로컬은 `setx`.
검증 후 워밍 크론 4대 제거(백업 `crontab.bak-0827-0734`).

**결과**: 5대 전부 108자 토큰 확인. Calladmin 에서 `claude -p` 실행 시 `is_error:false`.
재시작 후 상태바 정상(클로드 12%, 코덱스 1%).

| 복구 시 텔레그램 없음 | 발사 실패 시 10분마다 스팸이 됨 | 보냄 / 다른 문구 | 창이 열린 걸 즉시 모름 |
| 워밍 크론 제거 | 토큰이 1년이라 갱신 불필요 | 유지(감시 겸용) / DBServer만 | **감시·창 백업 상실** — 사용자가 매일 쓰므로 직접 감지 |

## 3. 시행착오

- **잘못된 가정**: "토큰 수명 4시간 + 크론 4시간 = 여유 2초라서 로그인이 자주 풀린다."
  **발견 경위**: 사용자가 "실패해도 로그인은 안 풀렸고 한 달에 딱 한 번 풀렸다"고 반증.
  로그를 다시 보니 08-20 에 **4연속 실패(16시간)** 후 다음 회차가 그냥 성공했다.
  **복구**: 진단 철회. 갱신용 토큰이 살아 있으면 자동 복구된다.
  **교훈**: 사용자 관찰이 데이터고 내 추론은 가설이다. 충돌하면 관찰이 이긴다.

- **잘못된 가정**: "여러 기기가 같은 계정으로 갱신하며 서로 밀어낸다."
  **발견 경위**: 5대 갱신용 토큰 지문이 전부 달랐다(각자 독립 로그인).
  **복구**: 가설 폐기. 대신 SportedAWS 만 장수명 토큰이라는 **진짜 답**을 발견.
  **교훈**: 가설 검증용으로 뽑은 데이터에 답이 들어 있을 수 있다.

- **잘못된 가정**: `claude auth status` 로 워밍을 대체할 수 있다.
  **발견 경위**: 첫 시도에서 `rc=0` 이 나와 성공으로 봤는데, 그건 **파이프 뒤 `head` 의 종료코드**였다.
  파이프 없이 다시 재니 `rc=124`(타임아웃). TTY 를 붙여도 동일.
  **복구**: 대체 후보에서 제외. **교훈**: `cmd | head` 의 `$?` 는 `head` 것이다.

- **잘못된 가정**: DBServer 의 claude 가 Node 18 을 쓴다.
  **발견 경위**: `ls /root/.nvm/versions/node/*/bin/claude | head -1` 이 알파벳 순으로 v18 을 먼저 내놨다.
  `command -v claude` 는 v22.23.2 였다. **복구**: 사용자에게 정정.
  **교훈**: 파일 존재와 실제 사용 경로는 다르다.

- **잘못된 처방(2회)**: 토큰 입력을 `read -s` / `-AsSecureString` 로 **숨겼다.**
  **발견 경위**: 서버 3대와 로컬에 빈 값이 들어갔다. 입력이 안 보이니 실패도 안 보였다.
  **복구**: 보이는 입력 + 결과 검증(`grep -c oat01` / `.Length`)으로 전환.
  **교훈**: 보안을 챙기려다 **실패를 은폐하는 설계**를 만들면 안 된다.

- **사고(2회)**: 사용자가 **실제 토큰을 대화에 붙여넣었다.** 한 번은 발급 화면 전문,
  한 번은 PowerShell 에러 메시지(명령줄이 통째로 포함된다).
  **복구**: 즉시 알리고 폐기·재발급 안내. **교훈**: §4 참조.

## 4. 발견한 코드베이스 함정

### 4-1. 🔴 `resetsAt` 은 열린 창에서도 1초 흔들린다

"열림=고정, 닫힘=이동" 규칙은 맞지만 **고정을 정확 일치로 판정하면 안 된다.**
실측 4건 전부 `moved=1000ms`(부호는 ±). 허용 오차 없이는 열린 창이 주기적으로 닫힘으로 읽힌다.

같은 비교가 **두 곳**에 있었다 — 종료 판정과 프라이머 검증. 한쪽만 고치면 반쪽이다.

### 4-2. 🔴 `getCodexHomeUri()` 는 워크스페이스 기준이다 — 로컬 프로세스에 먹이지 마라

확장은 `extensionKind: ["ui"]` 라 **항상 로컬**에서 돈다. 그런데 이 함수는 워크스페이스를 보므로
Remote-SSH 창에서는 **서버 홈**을 돌려준다. 그 `fsPath` 를 로컬 `fs`/`cp.exec` 에 넘기면
`\root\.codex\…` 같은 값이 만들어진다.

같은 구멍이 [extension.ts:2871](../../src/extension.ts#L2871)(패널 게이트)에도 있다 — 별도 트랙.

### 4-3. 🔴 "읽을 수 없음"을 "위험함"으로 접으면 기능이 조용히 죽는다

`codexBillingHazard()` 가 ENOENT 를 hazard 로 반환 → `api-key-present` outcome →
`setCodexAutoStartBlockOnReset(false)`. **설정 파일에 영구 기록**되므로 재시작해도 안 돌아온다.
사용자는 "알림은 오는데 리셋이 안 된다"만 보게 된다.

클로드 쪽은 환경변수를 보므로 "못 읽음" 상태 자체가 없다. **코덱스에만 생긴 상태를
클로드의 처리에 재사용한 것**이 사고의 구조다.

### 4-4. 🔴 엣지 트리거만으로는 닫힌 상태에서 못 빠져나온다

`wasOpen && !isOpen` 은 한순간이다. 그 순간을 놓치면(자동시작 OFF·프라이머 실패·창 방치)
**다시 오지 않는다.** 시간 기반 복구가 없으면 영구 정지다.

### 4-5. 확장의 사용량 조회는 Session Key 다 — 자격증명 파일과 무관

[planUsage.ts:63](../../src/planUsage.ts#L63) 이 `Cookie: sessionKey=…` 로 claude.ai 를 호출한다.
`~/.claude/.credentials.json` 이나 `CLAUDE_CODE_OAUTH_TOKEN` 과 **완전히 별개 경로**다.
인증 방식을 바꿔도 상태바 표시에는 영향이 없다(실측 확인).

### 4-6. `claude setup-token` 은 저장하지 않는다 · 비대화형에서 멈춘다

- 1년짜리 토큰을 **화면에 출력만** 한다. `export CLAUDE_CODE_OAUTH_TOKEN=<token>` 은 사람 몫
- SSH 비대화형에서 **출력 0바이트로 무한 대기**. `timeout 30` 도 무시(SIGTERM 안 먹음).
  `claude auth status` 도 동일하게 rc=124
- 발급 화면에 `Store this token securely. You won't be able to see it again.` — 다시 못 본다

### 4-7. `.bashrc` 에 `export` 를 덧붙일 때 — 뒤에 붙은 빈 줄이 앞의 값을 죽인다

SportedAWS 는 70번 줄에 값이 있고 74번 줄에 빈 줄이 있었다. 셸은 순서대로 실행하므로
**나중 것이 이긴다.** `grep -c` 로 줄 수만 세면 "있다"로 보인다 —
`bash -lc 'echo ${VAR}'` 로 **실제 읽히는 값**을 확인해야 한다.

  — 감시 스크립트 도입을 사용자가 기각. 과잉 설계를 막았다.

  ②용어를 쉽게 풀 것. 적용 범위: 전 세션.

- > "로그아웃되면 로그인만 내가 하고 나머지는 니가해"
  — 역할 분담 확정. 대화형 인증만 사용자, 나머지 전부 내 몫.
