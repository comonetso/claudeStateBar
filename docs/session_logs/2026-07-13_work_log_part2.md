## 1. 작업 흐름 (커밋으로 복원 불가한 맥락)

### 1-1. 사용자 발상 — "알림만 받지 말고, claude -p로 블록을 열 수 없나"

**배경/요구**: 기존에 5시간 세션 리셋 시 텔레그램 알림이 오고 있었음. 사용자가 "알림을 주기도 하지만, `claude -p`로 아무거나 메시지를 날리면 (블록이) 시작하지 않을까"라고 제안.

**핵심 사실**: 5시간 블록은 **첫 메시지 시각에 앵커**된다. 04:00 리셋 + 08:00 첫 프롬프트 → 블록은 08:00~13:00. 따라서 리셋 시각에 더미 프롬프트를 쏘면 블록 경계를 리셋 시각에 고정할 수 있다.

**처리**: 신규 [src/blockPrimer.ts](../../src/blockPrimer.ts) + [extension.ts](../../src/extension.ts) 연결. v1.7.34 → 최종 v1.7.36.

**결과**: 컴파일 통과, .vsix 로컬 설치 완료. **마켓플레이스 배포는 사용자 지시로 보류** (태그 미푸시).

### 1-2. 설계 3요소가 이미 코드에 다 있었음

- 리셋 감지 지점: `detectSessionReset()` (텔레그램 발송이 여기 한 곳뿐)
- 프로세스 실행: `child_process`가 이미 import되어 사운드 재생에 `cp.exec(..., {windowsHide:true})` 사용 중
- 리셋 시각 데이터: `lastUsage.sessionResetAt` (ISO)

→ 새 의존성 0개.

## 3. 시행착오 — ★ 이 세션의 핵심

**잘못된 가정 (v1.7.34 원안)**: `claude -p`가 `exit 0`으로 끝나면 구독 5시간 블록이 열린 것이다.

**발견 경위**: 사용자 지적 — *"Anthropic이 `claude -p`는 구독제가 아니라 API 비용으로 청구한다고 했다가 거둬들였다. 나스닥 상장까지 유예. 만약 그렇게 되면 이걸로는 불가능한 거잖아?"*

**왜 치명적인가**: 정책이 전환되면 `claude -p`는 **실패하지 않는다 — 성공한다.** exit 0, 응답 정상, 다만 (a) 구독 창은 안 열리고 (b) API 크레딧이 빠져나간다. 즉 **조용한 실패가 아니라 조용한 과금**이며, 리셋마다 하루 4~5회 무기한 반복된다.

**복구 (v1.7.35, 3중 안전장치)**:
1. **사전 거부** — `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`이 env에 있으면 아예 발사 안 함 (그 호출은 구독이 아니라 API로 나감)
2. **사후 검증** — 발사 10초 후 usage 재조회 → `sessionResetAt`이 **실제로 미래로 이동했는지** 확인. 구독 블록이 열렸다는 증거는 exit 코드가 아니라 **이것뿐**
3. **자동 정지** — 검증 실패 시 `autoStartBlockOnReset`을 **즉시 OFF** + 텔레그램/VS Code 경고

**교훈 한 줄**: **외부 서비스의 과금 정책에 의존하는 자동화는 "성공했다"는 신호(exit 0)를 믿지 말고, "내가 의도한 자원이 실제로 소비됐는지"를 독립 채널로 검증하고 아니면 스스로 꺼져야 한다.**

## 4. 발견한 코드베이스 함정

- **`claude -p`는 stdin을 3초 기다린다** — 파이프 입력이 없으면 `Warning: no stdin data received in 3s`를 뱉고 진행. `cp.exec()` 반환 ChildProcess에 `child.stdin?.end()`를 호출해 즉시 닫아야 3초가 사라진다.
- **Claude Code의 프로젝트 디렉토리 인코딩은 cwd 기반** — `<tmp>/claudeStateBar-primer`에서 실행 → `~/.claude/projects/C--Users-bluec-AppData-Local-Temp-claudeStateBar-primer/`. **실측 확인함.** 이 성질 덕에 "전용 cwd로 실행 → 디렉토리명 substring으로 필터" 패턴이 성립.
- **현재 이 머신에 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` 없음 (실측)** — 즉 `claude -p`는 구독(OAuth) 자격으로 돌고 있다. 나중에 키를 넣으면 그 순간부터 API 과금 경로가 열린다.
- **개발 중 .vsix 재설치는 반드시 버전을 올릴 것** (이월 함정 — 안 올리면 옛 코드가 계속 돎). 이 세션에서 1.7.34→35→36으로 3번 올림.

### 9-1. 즉시 처리 필요

### 9-2. 검증 미완
- **★ 프라이머 실전 검증 — 다음 5시간 리셋 때** 출력 채널 `claudeStateBar`의 `[primer] ...` 줄로 판가름:
  - `[primer] verified — subscription window is open until ...` → **성공** (구독 블록 열림)
