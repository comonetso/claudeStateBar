## 1. 작업 흐름 (시간순)

### 1-1. thinking/진행 실시간 표시 실효성 조사
**배경**: 사용자 "Opus/Sonnet이 1~3분 침묵하다 한꺼번에 답을 쏟는다. 그 과정을 보고 싶다. 실효성 판단해줘."
**처리**: 현재 세션 jsonl 직접 파싱.
**결과(확정 사실)**:
- Opus thinking 블록은 `thinking` 평문 **빈 문자열**, `signature`(~1020자)만. → 사고 내용 디스크에 없음.
- jsonl은 블록 완성 단위 append(토큰 스트리밍 아님). 긴 사고/작성은 끝나야 기록.
- 대화형 세션 토큰 실시간 관측 공식 수단 없음(claude-code-guide 확인).
- ★1차 오진: grep `"thinking":"."` 으로 "평문 기록됨" 결론 → raw 까보니 signature뿐. **즉시 정정**.

### 1-2. 사용자 고통 재정의 → "생존 모니터"
**배경**: 사용자 "thinking 내용은 안 봐도 돼. 살아있나/뻗었나/뭐하나를 알고 싶다."

## 3. 시행착오 / 사이드퀘스트 ★

- **잘못된 가정 1**: grep `"thinking":"."` 매칭으로 "Opus thinking 평문 기록됨" 결론. → raw 까보니 `thinking`=빈 문자열, signature만. **PowerShell ConvertFrom-Json으로 즉시 정정**. 교훈: grep OR 매칭(signature 포함)을 평문 존재로 오인 금지.
- **잘못된 가정 2(가장 큰 노력 손실)**: 별도 패널+풍부표시(타임라인/현재활동)가 유용할 거라 가정. → 사용자 "채팅 재탕 무의미" 판정. 전면 롤백. 교훈: **"채팅창에 이미 나오는 것"을 다른 UI에 재표시하면 무의미**. 진짜 가치는 채팅에 없는 것(경과초=살아있음 신호)에만.

## 4. 발견한 코드베이스 함정 ★

- **Opus thinking 평문 없음**: jsonl thinking 블록 `thinking`=빈 문자열, `signature`만 ~1020자. 사고 내용 표시 원천 불가.
- **jsonl 블록 완성 단위 append**: 긴 사고/작성 구간은 끝나야 기록 → 그 침묵 동안 디스크 무변화. (직전 박제 재확인)
- **★짧은 도구는 상태바에 안 잡힘**: 30초 폴링 + 파일와처가 `pendingToolUseAt` 있는 순간을 놓침. 도구는 1~2초라 그 사이 refresh가 안 돎 → `🔧` 거의 안 뜨고 `🤔`(사고)만. 긴 도구(권한 대기 등)는 잡힐 것.
- **SessionInfo 단계 신호 필드 기존 존재**: `lastActivityAt`/`lastAssistantEndTurnAt`/`pendingToolUseAt`/`pendingQuestionAt`(extension.ts:38~48). getLatestTokenCount이 채움. 추가 파싱 불필요.
