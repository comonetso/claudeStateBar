## 1. 작업 흐름 (시간순)

### 1-1. 작업1 — 워크플로우 카드 제목 옆 시작/경과 시각 (v1.7.17)
**배경**: 사용자 "제목 네모 부분에 시작시간(H:i:s) / 경과시간(i:s)".
**처리**:
- `WorkflowInfo`/`WorkflowView`에 `startedAt`/`endedAt`(epoch ms) 추가.
- `getAgentTiming`이 버리던 `firstTs`/`lastTs`를 반환 → 워크플로우 루프에서 `startedAt=min(firstTs)`, `endedAt=max(lastTs)` 집계.
- `parseTaskAgent`도 `lastTs` 반환 → Task 번들 `startedAt=batch[0].firstTs`, `endedAt=max(lastTs)`.
- webview: 제목줄에 `.wf-time` span(`🕘 11:24:16 · 경과 00:28`). `setInterval(tickElapsed, 1000)`로 진행 중 1초씩 카운트업, 완료 시 `data-done`(endedAt) 기준 `소요 mm:ss` 고정.
- CSS: `.wf-name flex:0 1 auto`, `.wf-time`, `.wf-spacer flex:1`로 제목 옆 배치.
**결과**: 컴파일 통과, 사용자 실기기 확인 OK ("경과 00:28 카운팅 잘 됨").

### 1-2. 작업2 1차 — 진행내용 전체 표시, 토글 제거 (v1.7.17)
**배경**: 사용자 "내용이 많더라도 쩜쩜쩜 말고 전체 내용이 나오게" + "계속 갱신되니 토글로 하면 바로 원복되어 의미없음".
**처리**: `<details>` 토글 제거, `fullSummary` 전체를 `.summary`에 인라인 표시(pre-wrap). openDetails/captureOpenDetails/toggle 리스너 제거.
**결과**: v1.7.17 빌드·설치. → 사용자 "내 의도와 완전히 다르다".

### 1-3. 작업2 2차 — step-by-step 누적 시도 후 원복 (실패 → v1.7.18 기반)
**배경**: 사용자 진짜 의도 = "에이전트가 한 단계 하고 내용 나오고, 또 한 단계 하고… 진행 과정을 계속 갱신하며 누적 표시".
**처리(시도)**: `accumulateAgentSteps`/`stepsPreview` 헬퍼 추가, `getAgentTiming`을 "마지막 1개"→"전체 누적"으로 재작성, 워크플로우 루프 `hasSteps` 분기.
**중단 사유**: 실제 토론 에이전트 로그 분석 결과 → **agent-*.jsonl은 토큰 스트리밍이 아니라 완성 메시지 단위 append**. 토론(도구 미사용)은 `assistant text(5683자)` 단 1줄 = 단계 1개. 누적해도 효과 없음.
**처리(원복)**: 사용자 "이 부분만 원복해" → `getAgentTiming`·워크플로우 루프 누적 변경 전부 되돌림. (firstTs/lastTs 반환은 작업1용이라 유지)

### 1-4. 작업2 3차 — 미리보기 2배 + done 토글 (v1.7.18)
**배경**: 사용자 "전체는 그렇고, 일부만 보여주더라도 이전보다 좀 더 많이. 끝나면 토글로 전체 유지. 이전 2배 정도, 테스트 후 조절".
**처리**: webview `PREVIEW_CHARS=320`(160의 2배), `preview=fullText.slice(0,320)`. **done 에이전트만** `<details>` 토글(데이터 고정 → 갱신해도 안 닫힘), running은 미리보기만. openDetails/toggle 리스너 복원, CSS details/.full 복원.
**결과**: v1.7.18 빌드·설치. 사용자 검토 워크플로우 2마리로 확인.

### 1-5. 작업2 4차 — 완전 원복 (v1.7.19, 최종)
**배경**: 사용자 "이거는 이전대로 하자. 완전히 원복시켜. 너무 정신이 없어."
**처리**: `PREVIEW_CHARS` 제거, summaryHtml을 v1.7.16 원본(160자 `a.summary` 미리보기 + `full>summary`면 토글)으로 복원. **작업1 시간 표시는 유지**(불만 없었음).
**결과**: v1.7.19 빌드·설치. 미리보기는 원래대로, 시간 표시만 추가된 최종 상태.

## 3. 시행착오 / 사이드퀘스트 ★

- **잘못된 가정 1**: "진행 내용 전체가 나오게" = 전체 텍스트 인라인 표시로 해석.
  - **발견**: 사용자 "내 의도와 완전히 다르다 / 결과를 한 번에 쫙 말고".
  - **진짜 의도**: 진행 과정을 단계별로 누적하며 갱신.
- **잘못된 가정 2**: 누적하면 step-by-step이 보일 것.
  - **발견**: 실제 토론 에이전트 로그(`agent-*.jsonl` 4줄, text 1개)를 직접 읽어보니 완성 메시지 단위 append. 도구 없는 작업은 단계 1개.
  - **복구**: 누적 변경 원복. 미리보기 양만 늘리는 절충(2배)으로 전환.
- **최종**: 2배(320)도 "정신없다" → 완전 원복(160 + 토글). 시간 표시만 남김.
- **교훈**: 사용자가 "전체를 보여줘"라 해도, 실제 정답은 "적당량 미리보기 + 완료 시 토글". 표시량은 한 번에 정하지 말고 실물 보며 조절. UI 표시는 데이터 구조 한계(스트리밍 아님)부터 확인.

## 4. 발견한 코드베이스 함정 ★

- **agent-*.jsonl은 토큰 스트리밍이 아니라 "완성된 assistant 메시지 단위"로 append**. 도구 없이 긴 텍스트 한 방 내는 작업(토론·요약)은 진행 중 로그가 비었다가 완료 시 통째로 기록 → 진행 표시(step-by-step) 불가. 도구 쓰는 작업에서만 단계가 여러 줄.
- **(review-pair 발견) tickElapsed: allDone인데 `wf.endedAt` 부재 시 경과 시계가 안 멈춤** — `data-done` 빈 문자열 falsy 의존. endedAt 폴백 권장 (미적용, §9 별도 트랙).
- **(review-pair 발견) findTaskAgentBundles `startTs=batch[0].firstTs`는 Math.min이 아니라 정렬 의존** — 현재 firstTs 오름차순 정렬이라 동치이나, 정렬 방식 바꾸면 조용히 깨짐. 워크플로우 쪽 Math.min 패턴과 비대칭 (미적용, §9 별도 트랙).
- **workflowsSignature(extension) vs sigOf(webview) 수동 중복** — 한쪽만 필드 추가 시 "데이터 왔는데 안 그려짐" 버그. 둘 다 startedAt 추가 시 동기화함.

## 5. 사용자 핵심 발언 박제 ★

- > "계속 갱신이 되기 때문에 토글로 구현하면 바로 원복되어 의미없음"
  - 맥락: 진행 중 에이전트 표시 방식 논의.
  - 적용: 자동 갱신되는(데이터 변동) 항목엔 토글/펼침 상태가 무의미. 토글은 데이터가 고정된(done) 항목에만.
- > "전체를 보여주는 건 그렇고, 일부만 보여주더라도 이전보다 쫌 더 많은 내용. 테스트 해보고 양은 조절"
  - 맥락: 표시량 합의.
  - 적용: UI 표시량은 한 번에 확정 말고 상수화 → 실물 보며 조절. (결국 원래대로 회귀했지만 "실물 확인 후 결정" 원칙은 유효)
- > "너무 정신이 없어 / 완전히 원복시켜"
  - 맥락: 미리보기 2배도 과함.
  - 적용: 정보 밀도 과하면 사용자 인지 부하. 기본은 적게, 더 보려면 토글.
