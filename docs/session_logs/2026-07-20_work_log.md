## 4. 발견한 코드베이스 함정 (★ 이 세션의 핵심)

- **[claude.ai usage API — `sessionResetAt` 세만틱]** 리셋을 *감지*하는 유일한 신호는 `sessionResetAt`이 새 값으로 바뀌는 것인데, 그 새 값은 **이미 미래(블록 열림)**다. 그래서 [blockPrimer.ts](../../src/blockPrimer.ts) `fireOnReset()`은 "미래=블록 열림"으로 보고 **매 리셋 skip**한다. **"리셋 감지 시점"과 "발사가 유의미한 시점(블록 닫힘)"이 상호 배타적** — 프라이머 설계의 근본 딜레마.
- **[`sessionResetAt` 밀리초 흔들림]** 정상(블록 열림) 상태에서도 폴링마다 resetAt이 **0.7초 폭으로 흔들린다**(`17:49:59.6`~`17:50:00.3`). 서버가 요청 시각 기준 재계산하는 듯. → [extension.ts](../../src/extension.ts) `detectSessionReset()`의 `prev !== current` 판정이 정상시에도 거의 항상 참 → 유일한 게이트는 `prevTime <= now`. **리셋 근처에서 중복 알림을 유발할 수 있음**(사용자 스크린샷에 "오전 12:00" 리셋 알림 2연속 관측).
- **[`claude -p`는 열린 블록에선 사용량만 축낸다]** 블록이 열려 있을 때(future=Y) 발사하면 새 블록을 여는 게 아니라 기존 블록 사용량만 소비(실측 17→19%). → 리셋 감지 시점의 skip은 **오히려 올바른 방어**(안 그러면 낭비).
- **[`claude -p`는 구독 자격으로 돈다 — 현재는]** 발사 후 session% 상승 = 구독 사용량에 반영. API 과금 아님(env에 API 키 없음, §이전 로그와 일치). 프라이머 3중 안전장치가 대비한 "정책 전환"은 아직 발생 안 함.
- **[프라이머는 VS Code 창이 떠 있어야만 작동]** 확장은 VS Code 프로세스 내에서 돎 → 새벽 리셋 시각에 VS Code(해당 창)가 꺼져 있으면 발사 시도조차 안 함. **Electron 트레이 앱이라면 백그라운드 상시 실행으로 이 한계가 없음** — 단 프라이머 원리가 성립해야 의미(§9-2).

## 12. [追記] v1.7.40 — 프라이머 발사 트리거 재설계 (session% 기반)

**절전 실측(04:11 깨어남)으로 근본 원인 최종 확정** — diag.log 궤적:
- **02:50:01(리셋 순간)** `resetAt=null, session=0%` 포착 = 블록 완전 닫힘. 그런데 `detectSessionReset`이 `current(resetAt)=null`이면 `if(prev && current)` 가드에 걸려 **스킵** → 발사 유효 순간을 놓침.
- 이후 resetAt이 미래(자정 `23:59:59`/`00:00`)로 채워짐 → future=Y → 설령 감지해도 skip.
- 절전 해제 후 여러 창(재로드 안 한 구버전 메모리)이 globalState 공유 race로 **텔레그램 3개 중복**.

**재설계 (v1.7.40)**:
- 트리거: `sessionResetAt 변화` → **`session% >0 → 0` 전이(블록 닫힘)**. resetAt은 닫혀도 미래라 무용, session%만 신뢰 가능.
- globalState `lastSessionPercent`로 전이 판정 → **절전 건너뛰어도 해제 후 첫 폴링에 포착**.
- 중복 방지: **10분 버킷 이벤트 키 + 원자적 wx lock**(`claimResetEvent`) → 여러 창/폴링/절전버스트에도 텔레그램·발사 각 1회. globalState 공유가 1차 방어, lock이 2차.
- 검증: resetAt 이동 → **발사 후 session% 상승**. 실패해도 API 키 있을 때만 자동 OFF(절전 오판 방지).
- 코드: `blockPrimer.fireOnReset→firePrimer`(future체크·자체lock 제거), `claimFiring→claimResetEvent`, `detectSessionReset→detectBlockClose`, credentials `get/setLastSessionPercent` 신설.

**남은 한계**: 컴퓨터 절전/종료 중엔 폴링 자체가 멈춰 그 순간 발사 불가 — 해제 후에야. 완전 해결은 OS 작업 스케줄러(리셋 시각 wake + `claude -p`). 별도 트랙.

**검증 상태**: 컴파일 통과 / v1.7.40 로컬 설치. **실전(다음 블록 닫힘) 발사 미검증** — 현재 session 3%(열림)라 트리거 대기. 모든 VS Code 창 재로드 필요(구버전 메모리 창 잔존 시 중복). README 미반영(실전 검증 후).

## 14. [追記] 2026-07-21 실전 검증 완료 + v1.7.43 (앵커 모델 확정 + 검증/기상 발사 수정)

### 14-1. 앵커 모델 확정 (raw 실측 — 내 억측 정정)
세션 중 "고정 시간 그리드" 억측 → 사용자 강하게 반박(첫 메시지=0% 시작이 원칙). raw usage 응답 덤프(v1.7.42)로 **앵커 모델 최종 확정**:
- **17:00 리셋 → util 14%→0% → 17:13까지 안 열림(자동 순환 X)** → 사용자 **17:10 첫 메시지** → `resetAt=22:10 = 17:10+5h`.
- **22:10 리셋 실측**(사용자 방치): block-closed 감지 → 프라이머 자동 발사(exit0) → `resetAt=03:10 = 22:10+5h`. **발사와 리셋 21초차** → 리셋 시각 앵커 사실상 달성.
- **핵심 함정**: `session=0%`(블록 닫힘)일 때 `sessionResetAt`은 **weekly 리셋값(fallback)**을 반환(예 07-25). 블록 열림일 때만 first+5h. → 프라이머 검증은 resetAt이 `now+5h(≤6h)` 범위로 왔는지로 판정해야(주간은 며칠 후라 걸러짐).
- **더미는 util을 안 올린다**: `claude -p "ok"`는 너무 작아 session% 0% 유지. 그래서 "session% 상승" 검증(v1.7.40)이 오탐. resetAt 이동이 유일한 열림 신호.

### 14-2. v1.7.43 수정
- **검증**: session% → **resetAt이 now+5h(≤6h)로 이동**했는지. 반영 ~1분 걸려 15초×5회 재시도.
