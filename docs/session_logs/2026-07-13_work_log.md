## 1. 작업 흐름

### 1-1. jacobian-lens 검토 (적용 불가 판정)
**배경/요구**: 사용자가 `https://github.com/anthropics/jacobian-lens` 를 확장에 적용 가능한지 검토 요청.
**처리**: README fetch. Anthropic 논문 *"Verbalizable Representations Form a Global Workspace in Language Models"* 의 참고 구현. 모델 내부 residual stream을 평균 야코비안으로 최종 레이어에 사영해 unembedding으로 디코딩하는 interpretability 도구 (PyTorch + transformers, 오픈 웨이트 모델 대상).
**결과**: **적용 불가**. ①오픈 웨이트 가중치 직접 접근 필요 → Claude는 클로즈드 웨이트 ②우리 확장은 네트워크 없이 JSONL 디스크 읽기만 함 ③런타임 상이(Python+CUDA vs Node/VSCode). 사용자 지시로 **"나중에 논의" 보류**.

### 1-2. 주간 한도 모델별 표시 복구 (본 세션 핵심)
**배경/요구**: 사용자 신고 — "주간한도에 Sonnet이 사라지고 Fable 5가 새로 등장, 이게 뉴노멀". 확장 툴팁의 모델별 주간 한도가 **한 줄도 안 나오는** 상태.
**처리**:
1. (1차 시도, 실패) `planUsage.ts`가 `seven_day_sonnet` / `seven_day_opus` 를 하드코딩 파싱 → `seven_day_*` **접두사 전체 동적 스캔**으로 변경. 여전히 0줄.
2. `logUsageSchema()` 진단 코드 추가 — 응답 top-level 키 + 발견된 per-model 버킷 + (버킷 0개일 때) raw body 를 출력 채널에 로깅.
3. 실제 응답 확보 → **스키마 자체가 바뀐 것 확인** (§4 참조).
4. `limits` 배열의 `weekly_scoped` 항목 파싱으로 전환. 모델명은 `scope.model.display_name` 에서 취득 — **모델명 하드코딩 0**.
**결과**: 컴파일 통과, v1.7.33 로컬 설치 완료. 사용자 툴팁 실확인은 세션 종료 시점 미완(§9-2).

## 3. 시행착오

- **잘못된 가정**: "Fable이 추가됐으니 `seven_day_fable` 키가 생겼을 것"
  - **발견 경위**: `seven_day_*` 전체 동적 스캔으로 바꿨는데도 Opus·Sonnet 포함 **0줄** 출력. 새 키가 생긴 게 아니라 버킷 체계 자체가 죽은 것.
  - **복구**: raw body 덤프 → `limits` 배열 발견.
  - **교훈**: 외부 비공식 API가 "값이 안 나온다"고 할 때, **키 이름을 추측하지 말고 응답 원본부터 찍는다.** 추측 2회 = 빌드 2회 낭비.

- **잘못된 가정 2**: "vsix를 같은 버전(1.7.31)으로 덮어쓰고 Reload Window 하면 새 코드가 돈다"
  - **발견 경위**: 디스크의 `out/extension.js` 에는 `logUsageSchema` 가 **있는데**(grep 확인) 출력 로그에는 해당 줄이 안 찍힘.
  - **복구**: 버전을 1.7.32로 **올려서** 재설치 → 새 확장 디렉토리 생성 → 즉시 반영.
  - **교훈**: §4 참조 (함정으로 승격).

## 4. 발견한 코드베이스 함정

- **[claude.ai usage API 스키마 변경 — 2026-07-13 확인]** 모델별 주간 한도가 `seven_day_<model>` 버킷에서 **`limits` 배열로 이전**됨. 레거시 버킷(`seven_day_opus`, `seven_day_sonnet`, `seven_day_cowork`, `seven_day_omelette` 등)은 키는 남아 있으나 **값이 전부 `null`** 인 껍데기.
  - 신 구조: `limits: [{kind:"session"|"weekly_all"|"weekly_scoped", percent, resets_at, scope}]`
  - 모델별 = `kind === "weekly_scoped"`, 모델명은 **`scope.model.display_name`** (예: `"Fable"`, `id`는 `null`).
  - 응답에 미사용 코드네임 슬롯이 다수 예약돼 있음: `tangelo`, `iguana_necktie`, `omelette_promotional`, `nimbus_quill`, `cinder_cove`, `amber_ladder` (전부 null) — 향후 여기에 모델이 붙을 수 있음.
  - `weekly_scoped` 항목의 `resets_at` 은 `null` 일 수 있음 → 주간 리셋 시각으로 fallback 필요.
  - `is_active` 는 표시 조건으로 쓰면 안 됨 (미사용 모델은 `false` → Fable이 숨겨짐).

- **[VS Code 확장 재설치 함정]** **같은 버전 번호로 vsix를 덮어쓰면 Reload Window 해도 옛 코드가 계속 돈다.** VS Code가 동일 버전이면 기존 확장 디렉토리를 재사용하기 때문. 디스크 파일은 갱신되어 있어서 grep으로는 "새 코드 맞다"고 오판하게 됨. → **개발 중 재설치는 반드시 patch 버전을 올린다.**
