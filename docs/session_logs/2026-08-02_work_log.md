## 1. 작업 흐름

### 1-1. 발단 — "키워드 넣어서 배포했나?"

세션을 연 이유가 이 한 줄이었다. 확인해 보니 v1.8.0/v1.8.1 모두 태그 9개가 정상 포함돼 배포돼 있었다(직전 6개에서 `codex`/`openai`/`chatgpt` 3개 추가된 상태).

이때 **"마켓은 keywords를 앞 5개만 인정한다"는 통설을 언급했는데 사실이 아니었다.** 공식 문서 확인 결과 상한은 30개다. 사용자가 "키워드가 확실해야 사용자들이 잘 찾지"라고 해서 실측 조사로 전환했다.

### 1-2. 1차 정제 — 25개 (폐기)

브랜드 / 핵심기능 / 성격·부가 / 모델명 4층으로 25개를 짰다. 여기에 사용자 선택으로 한글 4개(`클로드 토큰`·`코덱스 토큰`·`클로드 컨텍스트`·`코덱스 컨텍스트`)를 더해 29개까지 갔다.

### 1-3. 2차 재설계 — 사용자 지적으로 방향 전환 (채택)

> "브랜드 핵심기능 이걸 같이 검색하는 경우가 많을텐데 / 우리의 핵심은 각 프로바이더의 토큰사용량, 컨텍스트사용량을 한눈에 보는거쟎아"

**이 지적이 맞았다.** 1차안은 브랜드어와 기능어가 따로 놀아서 `claude token usage` 같은 실제 쿼리에 **정확 매칭되는 구가 하나도 없었다.** 프로바이더 × (토큰/컨텍스트/사용량) 조합 구 10개를 최상단에 깔고 3층 구조로 재배분했다.

최종 30개(상한):
```
조합 구(10)  claude token usage / claude context usage / claude usage monitor
             claude code usage / claude code monitor / claude context window
             codex token usage / codex context usage / codex usage monitor / codex cli usage
브랜드(8)    claude / claude code / claude ai / anthropic / codex / codex cli / openai / chatgpt
기능(8)      token usage / context usage / context window / token counter
             usage monitor / status bar / rate limit / usage limit
한글(4)      클로드 토큰 / 코덱스 토큰 / 클로드 컨텍스트 / 코덱스 컨텍스트
```

자리를 내주고 빠진 것: `ai assistant`, `ai agent`, `session monitor`, `workflow`, `remote ssh`, `telegram`, `quota`, `opus`, `sonnet`. 이 단어들은 description 본문에 이미 있어 전문 검색에는 여전히 걸린다.

### 1-4. 릴리즈

CHANGELOG는 사용자가 "이번 버전은 로그를 작성할 필요가 있을까"라고 물었으나, 마켓 CHANGE LOG 탭에 `1.8.2`만 비면 공백처럼 보이므로 **"기능 변경 없음"을 명시한 한 줄**로 넣었다. 커밋 `c63259e` → 태그 `v1.8.2` push → CI 배포.

## 3. 시행착오

- **잘못된 가정**: "마켓은 keywords를 앞 5개만 검색 태그로 인정한다"
- **발견 경위**: 사용자가 "키워드가 확실해야 한다"고 해서 공식 문서(extension-manifest)를 직접 확인
- **복구**: 실제 상한은 **30개**. 5개 제한을 전제로 한 "유입 큰 순서로 재정렬" 제안은 폐기하고, 상한까지 채우는 방향으로 전환
- **교훈 한 줄**: 마켓 메타데이터 관련 통설은 문서로 확인하기 전엔 전제로 삼지 않는다

## 4. 발견한 코드베이스 함정 (위키 스킵 — 전문)

### 4-1. `keywords` 상한은 30개이고, 이것이 곧 마켓의 Tags다

공식 문서(`code.visualstudio.com/api/references/extension-manifest`) 원문:
> "An array of **keywords** to make it easier to find the extension. These are included with other extension **Tags** on the Marketplace."
> "This list is currently limited to 30 keywords."

"앞 5개만 인정" 같은 제한은 문서에 없다.

### 4-2. `Other` 카테고리는 마켓이 버린다 (실측)

v1.8.1의 `package.json`은 `"categories": ["Other", "Visualization"]`이었는데, 마켓 gallery API가 반환한 값은 **`["Visualization"]`** 뿐이었다. `Other`는 등록조차 되지 않는다 → **넣을 이유가 없는 값**이다.

### 4-3. `AI` 카테고리는 공식 문서에 없지만 마켓은 인정한다 (실측)

- 공식 문서의 categories 목록에 `AI`는 **없다** (Programming Languages, Snippets, ... Testing까지만)
- vsce는 `src/package.ts`에서 카테고리를 **화이트리스트 검증하지 않는다** (`categories: (manifest.categories ?? []).join(',')` — 그냥 join)
- 마켓엔 `marketplace.visualstudio.com/search?target=VSCode&category=AI` 필터가 **실재**한다
- **v1.8.2 배포 후 API가 `["Visualization","AI"]`를 반환** → AI는 정상 등록됨

### 4-4. 마켓 반영 확인법 — gallery API (인덱싱 지연 약 4분)

웹 페이지는 클라이언트 렌더링이라 fetch로 태그·카테고리를 못 읽는다. POST API를 쓴다:

```bash
curl -s -X POST "https://marketplace.visualstudio.com/_apis/public/gallery/extensionquery" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json;api-version=7.2-preview.1" \
  -d '{"filters":[{"criteria":[{"filterType":7,"value":"blueming.claude-state-bar"}],"pageSize":1}],"flags":950}'
```

`version`, `categories`, `tags`, `statistics`(installs)가 그대로 나온다.
**배포 직후 조회하면 구버전이 반환된다** — 이번엔 100초·200초 대기 후 3차 조회에서 1.8.2가 잡혔다.

### 4-5. 한글 태그도 그대로 등록된다 (실측)

`클로드 토큰`·`코덱스 토큰`·`클로드 컨텍스트`·`코덱스 컨텍스트` 4개가 API 응답에 정상 포함됐다. (검색 유입 효과는 별개로 미검증)

### 4-6. CI의 Open VSX 단계는 계속 죽고 있다

`npx ovsx publish -p ` → `error: option '-p, --pat <token>' argument missing` → `exit code 1`.
`OVSX_PAT` 시크릿이 비어 있어서다. `gh run watch`가 단계별 ✓를 찍어 성공처럼 보이지만 하단에 `X Process completed with exit code 1`이 섞여 나온다 — **✓만 보고 판단하면 안 된다**(직전 세션에서도 잡힌 패턴).
