## 1. 작업 흐름 (시간순)

### 1-1. /clear 후 이중 세션 표시 버그 수정
**배경**: 사용자가 `/clear` 후 같은 프로젝트 세션이 2개 표시된다고 보고
**원인**: Claude Code가 새 세션 시작 시 이전 JSONL 파일 끝에 `{"type":"last-prompt",...}` 항목을 추가함 → 파일 mtime이 새 세션과 동시에 갱신 → supersession 로직이 어느 게 최신인지 판단 불가 → 둘 다 표시
**처리**:
- `TokenUsage`에 `lastRealTimestamp: Date | null` 필드 추가
- `getLatestTokenCount` forward pass에서 `type !== 'last-prompt'`인 엔트리의 마지막 `timestamp`를 추적
- `findActiveSessions`에서 `lastUpdated: file.mtime` → `lastUpdated: usage.lastRealTimestamp || file.mtime`
**결과**: 컴파일 통과, 실기기 검증 필요

### 1-2. 한글/특수문자/괄호 인코딩 수정
**배경**: 사용자 워크스페이스 경로에 한글(`바탕 화면`), 괄호(`재정(업무)`) 포함 → Claude 실제 디렉과 불일치
**원인 분석**:
- Claude Code는 비ASCII 문자(한글 등) 각각 → `-`, 괄호 등 특수문자 → `-`
- 우리 `encodeWorkspacePath`는 한글/괄호를 그대로 보존
- 실제 Claude 디렉: `d--OneDrive------` (한글 각 자 → `-`)
**처리**: `encodeWorkspacePath` 정규식 변경
  - 기존: `[:\\/\s_.]`
  - 변경: `[:\\/\s_.]|[^\x00-\x7F]|[^a-zA-Z0-9\-]` (모든 비ASCII + 영숫자/하이픈 외 특수문자 → `-`)
**결과**: 컴파일 통과, 실기기 검증 필요

### 1-3. hideAfter 기본값 상향
**배경**: 리눅스 서버에서 모든 세션이 `hideAfter=3600s(1시간)` 초과로 전부 필터링됨
**처리**: 기본값 3600 → 86400 (24시간), 최대값 86400 → 604800 (7일)
**결과**: 컴파일 통과, 적용 확인됨

## 2. 의사결정 로그

| # | 결정 사항 | 근거 | 검토한 대안 | 트레이드오프 |
|---|---|---|---|---|
| 1 | lastRealTimestamp 도입 | file.mtime은 last-prompt 때문에 신뢰 불가 | mtime 유지 + last-prompt 감지 후 mtime 역산 | 복잡도 증가 없이 정확한 타임스탬프 확보 |
| 2 | 비ASCII 전체 → `-` 인코딩 | Claude Code 동작과 일치시켜야 매칭 가능 | 한글만 예외 처리 | 경로에 한글 있는 경우 항상 `-` 연속으로 인코딩됨 |

## 3. 시행착오

- **잘못된 가정**: Claude Code가 비ASCII 문자를 그대로 보존할 거라 가정 → 실제 디렉 `d--OneDrive------` 보고 틀린 걸 확인
- **어떻게 발견했나**: Show Diagnostics 로그에서 encoded vs 실제 Claude 디렉 비교
- **교훈**: Claude Code 인코딩 규칙 = 영숫자/하이픈 제외 전부 `-`로 치환

---

## 4. 코드베이스 함정

- `{"type":"last-prompt"}` 엔트리: Claude Code가 새 세션 시작 시 **이전** JSONL 파일 끝에 추가함. `timestamp` 필드 없음. mtime 갱신됨 → supersession 오탐 원인
- Claude Code 경로 인코딩: 영숫자(`a-z`, `A-Z`, `0-9`)와 `-` 제외 **모든 문자** → `-` (한글, 괄호, 공백, 특수문자 전부)
- `hideAfter` 기본값이 짧으면 간헐적 사용 서버(원격 개발 등)에서 세션이 전부 숨겨짐
