## 1. 작업 흐름

### 1-1. 요구 발견 경위 — 폰 화면을 보고 시작됨

사용자가 리모트컨트롤(폰) 스크린샷 두 장을 보여줬다: 워크플로우 진행 카드(단계별 묶음·
모델·토큰 표시)와 CLI `/usage`·`/stats` 화면. "우리 확장은 왜 이렇게 안 보여주냐"는 질문에서
시작. 처음엔 데이터가 있는지조차 불확실해 "일단 조사부터"로 합의했다.

### 1-2. 데이터 출처 조사 — 7마리 워크플로우

`start_workflows` 관문을 통과해 Opus 7마리로 병렬 조사: 웹뷰 뼈대, 팝업 메뉴 통합, Usage
데이터 사양, Stats 캐시 스키마, 24시간 로컬 집계, 워크플로우 phase 파서, 토큰·모델 집계.
핵심 발견:
- `~/.claude/stats-cache.json` 에 CLI `/stats` 재료가 거의 그대로 있음
- 대화 기록의 `attributionSkill` 필드로 스킬별 비중 계산 가능
- 워크플로우 phase는 디스크 어디에도 기록되지 않고, **대본 파일을 정적 파싱해 되짚는 수밖에 없음**
- 토큰 집계는 "마지막 usage 레코드"가 정답(누적 합이 아님) — Claude Code 자체 `totalTokens`
  계산과 바이트 단위 일치로 검증

### 1-3. Opus 5 버그 발견과 범위 확장

사용자가 폰 화면과 비교하다 "Opus 5가 200k로 잡혀 있다"고 지적. 원인은
`getContextLimitForModel`의 `/opus[-_]?4/` 리터럴 매칭(버전 5를 못 잡음). 처음엔 Opus만
고치고 "Sonnet에도 같은 결함이 남아있다"고 보고했는데, 사용자가 "네 범위가 아니더라도
틀린 것은 바로 잡아야지, 모두 수정해"라고 명확히 지시 → Sonnet·모델명 표시(4곳)·CLAUDE.md
서술(6곳)까지 전부 수정.

### 1-4. 비용 카드 — 오판과 정정

세션 요약 카드(CLI 종료 요약 재현)를 만들 때 처음엔 "로그에 비용 필드가 없다"고
판단해 "$0.00 (구독)"만 표시했다. 사용자가 "이게 제일 중요해서 이 작업을 시작한 것"이라고
분명히 밝힘 → 재조사에서 `type: "cost-state"` 레코드(세션 정상 종료 시 기록, `totalCostUSD`·
`totalAPIDuration` 등)와 Anthropic 공식 API 단가표를 찾아 "API 환산" 기능으로 구현.
자세한 경위는 §3 참고.

### 1-5. 그룹 상태점 제거

워크플로우 패널의 phase 그룹 헤더 아래에 상태 점 줄(dot row)을 넣었는데, 실제로 2단계
워크플로우를 돌려 확인하니 사용자가 스크린샷과 함께 "쓸데없는 것 같아, 라인만 차지하고"로
판정. 아래 에이전트 행에 이미 같은 점이 있어 중복이었다. 즉시 제거.

### 1-6. start_workflows 스킬 개편

패널에 phase 그룹화 기능을 만들었는데, `start_workflows` 스킬에는 "언제 phase를 나눠야
하는지" 지침이 전혀 없었다(검색 결과 0건). 사용자가 "이 스킬은 확장과 관련 있으니 여기서
수정해도 된다"고 확인 → "역할을 먼저 분류하고 그 분류를 phase로 적는다"는 규칙을 추가,
`skill_cp_install`로 서버 4대에 SSH 직접 배포·검증(바이트 단위 일치 확인).

## 3. 시행착오

### 3-1. "비용은 로그에 없다"는 성급한 판단

**잘못된 가정**: 이번 세션 대화 기록 파일 하나만 열어보고 `costUSD`가 없다고 결론 내림.
**발견 경위**: 사용자가 "다른 자료에 보면 분명히 비용 나온다고 하더라, 잘 뒤져봐"라고
재조사를 요구.
**복구**: 전체 프로젝트 디렉토리를 `grep -rl`로 훑으니 `cost-state` 타입 레코드가 실제로
존재(진행 중 대화에는 없고 **세션이 정상 종료될 때만** 기록됨 — 그래서 이번 세션 파일에는
없었던 것). 여기에 공식 API 단가표를 곱하는 환산 기능을 추가로 구현.
**교훈**: "파일 하나 확인 = 전체 확인"이 아니다. 특히 이벤트성 레코드(종료 시에만 쓰이는 것)는
살아있는 세션 파일에는 애초에 나타나지 않는다. [[feedback_verify_before_documenting]] 사례로
추가할 만함.

### 3-2. README 편집 스크립트가 파일을 비움

Python 스크립트로 `README.ko.md`를 고치던 중 UnicodeEncodeError로 죽었는데, 파일을 열자마자
비우고 쓰기 직전에 예외가 나 **0바이트로 남았다.** git에 커밋된 상태라 `git restore`로 즉시
복구, 내용 손실 없음. 이후 임시파일에 쓰고 `os.replace`로 교체하는 방식으로 바꿈.

### 3-3. CHANGELOG 1차 작성이 개발일지가 됨

사용자가 "리드미/체인지로그 작업 내역 구구절절 넣지 마라, 특히 CHANGELOG는 절대"라고
지적(저번 세션에도 언급했던 규칙 — [[feedback_public_doc_tone]] 참고). 1차 작성본(76줄)에
실측 수치·함수 동작·모델 ID 문자열 대조가 그대로 들어가 있었음. 기존 1.13.0(22줄)·
1.14.0(55줄) 톤과 대조해 35줄로 재작성.

## 4. 발견한 코드베이스 함정

### 4-1. `getContextLimitForModel`의 버전 매칭 결함 (수정 완료)

`src/providers/claude/modelLimits.ts`. Opus는 `/opus[-_]?4/` 리터럴 문자열 매칭이었다
(Sonnet은 이미 버전 파싱 방식이었는데 Opus만 예외). `claude-opus-5`가 매치되지 않아 200k
기본값으로 떨어지고, 실제 1M 세션에서 사용률이 450%대로 표시될 수 있었다. 실측: 이 머신의
한 세션이 913,411 토큰까지 감.

수정 후 버전 매칭에도 함정이 있었다 — `claude-3-opus-20240229` 같은 옛 ID의 **날짜를
버전으로 오인**(`opus-20240229` → "버전 20"). `(?!\d)` 부정 전방탐색으로 방지. Sonnet
쪽에도 같은 결함이 원래부터 있었음(`claude-3-sonnet-20240229` → 1M 오판정, 사용자 지시로
같이 수정).

### 4-2. `getShortModelName`의 compact 인자는 죽은 코드였다

`src/providers/claude/display.ts`. 주석은 "compact 모드에서 S4.5로 축약"이라 적혀 있었지만,
`abbrev` 변수는 대입만 되고 한 번도 읽히지 않음 — 모듈 분리(980c7f8) 이전 원본까지 대조해도
처음부터 이랬다. **compact 모드는 프로젝트 이름만 줄이고 모델 이름은 그대로 두는 게 실제
동작**이었다. 주석이 거짓이었을 뿐 동작 자체는 정상이라 판정.

같은 함수에 실동작 버그 3개 추가 발견: `claude-opus-5[1m]`가 "Opus 1M"으로 표시(대괄호
접미사가 버전 탐지를 방해), `<synthetic>` 같은 placeholder id가 그대로 노출, Mythos 계열이
이름표에서 누락(한도는 1M을 받는데 이름은 숫자만 나옴).

### 4-3. 워크플로우 phase는 대본을 정적 파싱해야만 복원 가능

`journal.jsonl`은 `{type, key, agentId, result}` 4개 필드뿐, `*.meta.json`도
`{agentType, spawnDepth, model}` 뿐이라 phase 정보가 원천적으로 없다. 유일한 단서는
`workflows/scripts/*.js` 대본 파일. `src/workflowPhases.ts`에 소스 스캐너(문자열/주석 마스킹
+ 균형 괄호 절단)를 새로 작성해 `meta.phases`·`phase()` 호출·`agent()` 옵션을 코드 영역에서만
추출. 프롬프트 지문(40자 이상 정적 조각)으로 에이전트를 call site에 매칭.

**한계**: `pipeline()`은 단계가 시간상 겹칠 수 있어 시작 시각 기반 추정은 원리적으로
못 쓴다(조사 단계에서 확인, 이번 구현에서 채택 안 함). 변수로 넘긴 phase(`phase: d.key`)는
리터럴이 아니라 못 읽는다 — `start_workflows` 스킬에 "리터럴로 적어라" 규칙을 넣은 이유.

### 4-4. Task(Agent 도구) 서브에이전트 카드에 토큰·모델이 안 붙어 있었음

워크플로우 에이전트에는 토큰·모델을 넣었는데 `parseTaskAgent`(Agent 도구로 띄운 서브에이전트
전용 파서)에는 빠뜨렸다. 문서 정리 단계에서 뒤늦게 발견해 같은 방식으로 채움.

## 5. 사용자 핵심 발언

- > "너의 범위가 아니더라도 틀린 것은 바로 잡아야지.. 모두 수정해.." — Opus 5 버그를 고치며
  Sonnet의 동일 결함을 "범위 밖"이라 보고만 했을 때. 이후 발견되는 관련 버그는 지시받지
  않아도 함께 고치는 것이 맞다는 확인.
- > "내가 알고 싶은 것은 이 세션에서 사용한 비용이야. ... 지금 전체 금액이 나오는 것 같아" —
  세션별 비용 카드가 실제로는 세션 단위로 맞게 계산되고 있었는데도 사용자가 의심함. 다른
  세션과 값을 대조해서 실측으로 답변한 것이 신뢰 회복에 유효했다.
- > "README하고 CHANGELOG는 저번 세션에서도 언급했지만, 작업 내역 같은 걸 구구절절 넣으면
  안 되고 요점만 딱딱 간단명료하게 적어야 돼... CHANGELOG는 절대로 그렇게 적으면 안 돼" —
  릴리스 노트에 개발 일지를 쓰지 않는다는 원칙의 재확인. [[feedback_public_doc_tone]] 갱신
  대상은 아니고(이미 있는 규칙의 재적용 사례).
- > "일단은 문서부터 정리를 해놓자... 배포는 내가 조금 더 써보고 배포할 테니까" —
  이번 세션은 구현+문서 정리까지만, 마켓 배포는 사용자 판단으로 분리.
