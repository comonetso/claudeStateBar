## 1. 작업 흐름

### 1-1. 요구 접수와 정정

**배경/요구**: 사용자가 실사용에서 "1턴 끝나고 2턴째로 넘어갈 때 이전 턴들은 자동으로 접어라,
현재 턴만 활성화하는 게 맞다"고 요청. 1.12.0에서 넣은 턴 접기는 **수동**이라 기본이 전부 펼침이었다.

**처리**: 결정이 필요한 3건을 물었다 — ①적용 시점 ②수동 조작 처리 ③설정 키 여부.
①에 대해 나는 "항상 마지막 턴만"과 "진행 중일 때만"의 두 선택지를 냈는데, 사용자가 **세 번째 답**을 냈다:

> "패널을 처음 열 때는 첫 번째 턴이 오픈되어 있어야지. (…) 지난 대화를 다시 볼 때도 마찬가지로,
> 마지막 턴이 아니라 그럴 때는 첫 번째 턴을 열어야 처음부터 읽지."

읽는 **방향**이 상황마다 다르다는 것이었다. 새 답변은 최신을 보는 것이고, 지난 대화 복기는
처음부터 읽는 것이다. 내가 낸 두 선택지는 둘 다 "최신"만 상정하고 있었다.

**결과**: 비대칭 규칙으로 확정 — 처음 보는 대화 = 첫 턴, 새 턴 도착 = 마지막 턴.

## 4. 발견한 코드베이스 함정

### `folded` 맵의 "부재"를 고정된 기본값으로 읽으면 안 된다

1.12.0의 클릭 토글은 이랬다:

```js
folded[k] = folded[k] !== true;
```

`folded`에 값이 없으면 `undefined !== true` → `true`(접기). 기본값이 **항상 펼침**이던 동안에는
이게 정확히 맞았다 — 손대지 않은 턴은 펼쳐져 있으니 첫 클릭은 접기다.

포커스 규칙이 들어오면서 이 전제가 깨졌다. 이제 손대지 않은 턴도 **접혀 있을 수 있다**.
그 턴을 클릭하면 위 코드는 다시 `true`를 넣는다 — 화면상 아무 일도 일어나지 않고, 사용자에게는
**접힌 턴이 안 열리는 것**으로 보인다. 컴파일도 통과하고 하네스 없이는 눈에 띄지 않는다.

고친 방식은 렌더 시점의 실제 상태를 DOM에 실어 보내는 것이다:

```js
// turnHead
'<div class="turn-head" data-turn="' + esc(key) + '" data-fold="' + (isFolded ? '1' : '0') + '">'

// click
folded[el.getAttribute('data-turn')] = el.getAttribute('data-fold') !== '1';
```

**일반화**: 렌더 기본값이 정적에서 동적으로 바뀌면, 그 기본값을 읽던 **모든 토글 코드가 같이 깨진다.**
저장된 상태가 아니라 **그려진 상태**를 뒤집어야 한다. 같은 패턴이 `collapsed`(대화 카드 접기)에도
있지만 그쪽은 `chats` 수신 때마다 undefined가 반드시 채워져서(`collapsed[stamp] = i !== 0`)
부재 상태로 클릭될 일이 없다 — 그래서 손대지 않았다.

## 5. 사용자 핵심 발언

- > "지난 대화를 다시 볼 때도 마찬가지로, 마지막 턴이 아니라 그럴 때는 첫 번째 턴을 열어야 처음부터 읽지."

  선택지를 낼 때 **읽는 목적이 상황마다 다른지**를 먼저 따져야 한다는 뜻. UI 기본값 질문에 적용.

- > "이번 건 그냥 나한테만 설치하고 배포는 하지 않아도 될 것 같아. 하루에 배포를 너무 많이 하면 좀 그러니까."

  마켓 배포는 사용자 판단 영역이다. 빌드·로컬 설치는 자동이지만 **배포는 지시가 있을 때만**.
