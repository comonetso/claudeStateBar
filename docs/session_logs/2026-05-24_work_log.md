## 1. 작업 흐름 (시간순)

### 1-1. 컴팩트 모드에서 모델명 축약 해제
**배경**: 사용자가 컴팩트 모드에서도 모델명만은 `Sonnet`·`Opus` 풀네임으로 보길 원함

**결과**: 컴파일 통과

### 1-2. Context 임계값 비프음 알림 (1·2번 요청)
**배경**: 사용자가 컨텍스트 임계값 도달 시 청각 알림 원함. 경고 1×, 위험 2×.
**요구사항**: `warningThreshold` 도달 시 1번 비프, `dangerThreshold` 도달 시 2번 비프. 한 번만 울리고 임계값 내려가면 리셋.
**처리**:
- `import * as cp from 'child_process'` 추가
- `playBeep(count)` 함수 추가 (Windows/macOS/Linux 분기)
- `alertedSessions: Map<string, {warned, dangered}>` 모듈 전역 추가
- `isFirstScan` 플래그로 첫 스캔 무음 (오탐 방지)
- `refreshAllSessions()`에서 threshold crossing 감지 → 비프
- 세션 삭제 시 alertedSessions 정리
**결과**: 컴파일 통과

### 1-3. Claude 작업 완료 감지 비프 (3번 요청)
**배경**: 사용자가 "Claude가 작업 마쳤을 때" 알림 원함. JSONL 기반으로 가능한지 먼저 확인 요청.
**가능 여부 분석**: 가능 — JSONL의 `assistant` 엔트리 중 `message.stop_reason === 'end_turn'` 인 것의 타임스탬프를 세션별로 기억, 다음 refresh에서 새 타임스탬프 등장 시 비프. tool_use 중간 응답은 `stop_reason === 'tool_use'`라 자동 필터링.
**처리**:
- `TokenUsage` + `SessionInfo`에 `lastAssistantEndTurnAt: Date | null` 추가
- `getLatestTokenCount()` forward pass에서 end_turn 타임스탬프 추적
- `lastKnownEndTurnAt: Map<string, number>` 모듈 전역
- `playCompletionSound()` 신규 — 3음 오름 아르페지오 600→800→1000Hz
- `refreshAllSessions()`에 end_turn 변경 감지 로직 추가
- 세션 삭제 시 lastKnownEndTurnAt 정리
**결과**: 컴파일 통과, v1.7.0 → v1.7.1 bump

### 1-4. 설정 패널 비프음 테스트 섹션 (1차)

### 1-5. 비프음 디버깅 (실제 무음 원인 추적)
**배경**: 사용자 클릭해도 소리 안 남
**1차 시도**: 로그 보강 — `playBeep`/`playCompletionSound`에 exec 결과 로그, settings.js에 console.log + 버튼 DOM 인지 로그, settingsPanel handleMessage에 console.log
**결과**: 로그가 "[beep] command received → playBeep → exec → exec completed" 모두 정상 출력되는데도 무음

**2차 시도**: `[Console]::Beep`(PC 스피커 기반) → `[System.Media.SystemSounds]::Hand.Play()`(사운드 카드 기반) 전환
**결과**: 여전히 무음. 로그는 EXIT=0 정상.

**원인 발견**: `SystemSounds`는 **Windows 사운드 스킴 매핑**을 따름. 사용자의 사운드 스킴에서 Hand/Asterisk 항목이 "None"으로 설정되어 있으면 무음. PC 오디오 장치 자체가 아니라 시스템 알림 매핑을 통과해야 함.

**3차 시도**: `SoundPlayer.PlaySync()`로 표준 Windows WAV 파일(`C:\Windows\Media\chord.wav`, `tada.wav`)을 직접 재생 → 사운드 스킴 무시, 마스터 볼륨만 따름
**결과**: ✅ 동작 확인

### 1-6. WAV 파일 사용자 지정 변경
**요구**: `Windows Notify.wav`(경고) + `Windows Critical Stop.wav`(위험) + `tada.wav`(완료)
**처리**: `playBeep()` 분기에서 count별 wavFile 변수 분리
**결과**: 사용자 청취 확인 ("잘 나고 있어")

### 1-7. 사운드 사용자 설정화 (재빌드 없이 교체 가능)
**배경**: 사용자가 "C:\Windows\Media 안의 다른 파일로 나중에 바꿀 수 있게" 요청 → 설정 패널에서 직접 지정 방식 채택

### 1-8. MP3 지원
**요청**: WAV 외 MP3도 지원

## 3. 시행착오 / 사이드퀘스트 ★

### 3-1. `[Console]::Beep` 무음 — 사운드 스킴 추정의 함정
- **잘못된 가정**: PowerShell `[Console]::Beep(800, 250)`이 항상 PC에서 소리를 낸다고 생각
- **발견 경위**: 사용자가 "소리가 안 나"라고 보고 → 로그 추가 → exec 성공·EXIT=0 확인 → 그래도 무음
- **복구**: `SystemSounds`로 전환했으나 여전히 무음 → 결국 `SoundPlayer.PlaySync()` + 직접 WAV 파일 지정으로 해결
- **교훈**: Windows에서 PC 스피커 기반 비프(`Console::Beep`, `kernel32::Beep`)는 메인보드 스피커 없는 모던 PC에서 무음 가능. `SystemSounds`는 사운드 스킴 매핑에 의존. **소리 보장하려면 WAV 파일을 SoundPlayer로 직접 재생**.

### 3-2. 한글 표시 이름 ≠ 실제 파일명
- **잘못된 가정**: 사용자가 "알림.wav", "Windows 시스템 오류.wav"라고 말했을 때 그 파일이 실제로 존재한다고 생각하지 않고 매핑 추정만 함
- **발견 경위**: 사용자가 "내가 직접 들어본 것"이라 함 → PowerShell로 한글 파일명 확인 → 0건 → Windows 파일 탐색기가 **localize된 표시 이름**으로 보여주는 것이라 결론
- **복구**: 추정 매핑 (알림→`Windows Notify.wav`, 시스템 오류→`Windows Critical Stop.wav`)으로 진행 → 사용자 청취 확인
- **교훈**: Windows 시스템 사운드는 파일 탐색기에서 한글 displayName이 표시되지만, 디스크 파일명은 모두 영문. PowerShell `Get-ChildItem`이 진실의 원천.

### 3-3. 사용자 분노 발생
- **상황**: 컴파일만 하고 vsix 패키징을 안 한 채 보고 → 사용자 "야, 지금 컴파일 했어? VSIX로 내보냈냐고. 아, 짜증 나네 진짜."
- **교훈**: "컴파일까지 진행해" 지시 = 컴파일 + vsix 패키징까지가 한 묶음. 빌드 산출물 확인 가능한 상태로 보고해야 함. 다음부터는 `npm run compile && npx @vscode/vsce package` 묶음으로 처리.

### 3-4. 잡소리 비판
- **상황**: 빌드 단계에서 변경 설명 길게 늘어놓음 → "뭐 이렇게 잡소리가 많아?"
- **교훈**: 빌드/실행 결과 중심으로 간결하게. 설명은 사용자가 물을 때만.

## 4. 발견한 코드베이스 함정 ★

- **`[Console]::Beep` ≠ `SoundPlayer.PlaySync`**: 전자는 PC 스피커, 후자는 사운드 카드. Windows에서 소리 보장하려면 반드시 후자 + WAV 파일 직접 지정.
- **`SystemSounds`는 사운드 스킴 종속**: `[System.Media.SystemSounds]::Hand.Play()` 등은 Windows 설정의 사운드 스킴 매핑을 따름. 사용자가 스킴을 "소리 없음"으로 설정했으면 무음. 절대 신뢰 금지.
- **`WPF MediaPlayer`는 비동기**: MP3 재생 시 `Open()` 직후 바로 `Play()` 호출하면 무음. `NaturalDuration.HasTimeSpan`이 true가 될 때까지 sleep 폴링 필요.
- **`cp.exec` Windows 분기는 cmd.exe 경유**: PowerShell 명령 escape 시 single quote 내부의 `'`는 `''`로 두 번 써야 함 (`escaped = path.replace(/'/g, "''")`).
- **`vscode.env.remoteName`**: undefined면 로컬 UI 호스트, `'ssh-remote'`/`'wsl'`/`'dev-container'` 등이면 원격. `extensionKind: ['ui']` 명시했어도 원격에 강제 설치된 인스턴스가 있을 수 있어서 런타임 가드가 필요.
- **`SessionInfo.lastAssistantEndTurnAt`**: JSONL의 `entry.message.stop_reason`(NOT `entry.stop_reason`) 위치에 있음. PowerShell 출력으로 직접 확인했음.

## 5. 사용자 핵심 발언 박제 ★

- > "비프음은 어떤식으로 울리는지 어케 알지? 아직 컨텍스트가 도달을 안해서"
  - 맥락: 임계값 비프 구현 후 테스트 수단 없음 지적
  - 적용: **신규 기능 구현 시 검증 가능한 트리거(테스트 커맨드/패널 버튼)를 항상 동반 제공**. 임계값·이벤트 기반 기능은 인위적으로 발생시킬 방법이 없으면 무용지물.

- > "야, 지금 컴파일 했어? VSIX로 내보냈냐고. 아, 짜증 나네 진짜."
  - 맥락: 컴파일만 하고 vsix 안 만들고 보고함
  - 적용: **"컴파일까지" = 컴파일 + 패키징 한 묶음**. VS Code 확장 작업에서 사용자가 즉시 설치/테스트하려면 vsix가 있어야 의미 있음.

- > "뭐 이렇게 잡소리가 많아?"
  - 맥락: 빌드 결과 보고 시 변경 설명을 길게 늘어놓음
  - 적용: **빌드/실행 결과 보고는 산출물 중심으로 간결하게**. 변경 설명은 사용자가 물을 때만 또는 한두 줄로.

- > "졸라 맘에 안들어.."
  - 맥락: 기본 사운드(chord/tada) 마음에 안 든다는 표시 후 "나중에 교체 가능한지" 질문
  - 적용: **사용자 취향 영역(소리·색상·텍스트)은 항상 설정으로 노출**. 기본값은 동작 보장용일 뿐, 사용자 변경 경로가 없으면 마찰 발생.

- > "이슈를 정리한 다음에 finish하고 무중단으로 진행해. 나 잠깐 외출하고 올 테니까."
  - 맥락: 원격/로컬 사운드 적용 이슈 발생 → 사용자가 외출하면서 자율 마무리 지시
  - 적용: **"무중단으로 진행"**: 큰 방향이 컨펌된 후엔 디테일 자율 결정 + 끝까지 완료 후 보고. 중간 컨펌·질문 금지.

- > "중간에 끊지 말고 무중단으로 해."
  - 맥락: 위 발언 직후 재강조
  - 적용: 분명히 자율로 가라고 지시한 후엔 부가 질문도 자제. 단일 메시지로 끝까지 처리하고 결과만 보고.
