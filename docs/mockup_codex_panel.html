이 시안이 담고 있는 판단

① 카드 = 실행 1건. Claude 워크플로우가 "워크플로우 1건 = 카드"인 것과 같은 층위입니다. codex_rescue 실행 하나가 스탬프 하나이고, 그게 곧 카드 하나입니다.

② 아이템 = 이벤트 1건. 워크플로우의 "에이전트" 자리에 Codex의 item이 들어갑니다. item.started → 노란 펄스 점, item.completed → 초록 점. 데이터 모델이 거의 그대로 재사용됩니다.

③ agent_message를 주인공으로 세웁니다. 명령·검색은 한 줄로 접고, Codex가 한국어로 말하는 부분만 인용 블록으로 띄웁니다. 사용자가 실제로 알고 싶은 건 "무슨 명령을 쳤나"가 아니라 "지금 뭘 하려는 중인가"이고, 그 답이 여기 들어 있습니다. 위 두 개의 인용문은 지어낸 게 아니라 실제로 흘러나온 문장입니다.

④ 종류별 색. 말 / 명령 / 검색 / 파일 / 에러를 색으로 구분해 스캔이 빠르게 되게 했습니다. 상태바 쪽 규칙(색은 경고 전용)과 달리 여기서는 분류용이라 파스텔을 써도 신호가 흐려지지 않습니다.

⑤ 확정된 표시 규칙 — 아이템은 done(초록) · failed(빨강) · warn(노랑)으로 구분합니다. error 타입은 단순 안내도 같은 채널로 오므로 노랑이며, 진짜 실패는 turn.failed, 명령의 non-zero exit_code, file_change.status = failed로만 판정합니다. 카드 전체 상태는 아이템이 아니라 send.sh가 쓰는 status.json이 정하며, starting → running → finalizing → done / failed / stopped / stale로 전이합니다. 아이템 하나가 실패해도 카드 전체가 실패가 되지는 않습니다. finalizing은 Codex의 turn.completed 뒤에도 send.sh가 변경 감지·응답 회수·로그 보존을 계속하는 구간입니다. 이 구간을 따로 둬 아직 끝나지 않은 작업을 완료로 표시하지 않습니다.
