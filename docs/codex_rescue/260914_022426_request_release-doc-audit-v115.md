## 먼저 할 것
1. 감사 대상 문장을 한 줄씩 읽고, 각 주장에 대응하는 소스를 **실제로 열어** 대조해라.
2. 영문·한글 README 가 **같은 내용을 말하는지**(한쪽에만 있는 주장, 수치 차이)도 봐라.
3. **확인한 사실은 그때마다 응답 문서에 적어라.** 적는 순서는 맨 아래 `응답 저장 위치` 에 있다.

## 내(Claude)가 세운 판단 — 검토 대상일 뿐이다
- 설정 키, 메뉴 위치, 탭 이름, 150k 기준, 단가, Opus 5 한계 수정, 한국어 경과 시간 단위,
  placeholder 모델명 처리는 코드와 맞는다고 봤다.
- 자신 없는 곳 두 개:
  - README 370행/한글 339행 "긴 대화에서는 대개 캐시 읽기가 가장 큰 몫" — 코드에 근거가 있는 말이 아니라
    원래 문서에 있던 서술을 줄인 것이다. 과장이면 지적해라.
  - "이미 끝난 단계는 처음부터 접혀 있다" — 코드상 `running` 인 에이전트가 없으면 접힘으로 봤다.
    멈춘(stopped)·실패한 에이전트만 있는 단계도 접히는데, 문서가 그걸 "끝난"이라고 불러도 되는지.
- **이미 알고 있어서 이번 감사에서 빼는 것:** Fable 캐시 읽기 $0.25 가 Fable 5 에도 맞는지(코드 쪽 문제로 따로 기록함).

## 완료 게이트
- G1 감사 대상 **모든 주장**에 대해 참/거짓/근거 없음 판정이 있다
- G2 거짓·근거 없음 판정마다 **소스 파일:행** 근거가 있다
- G3 영/한 불일치 여부가 판정됐다
- G4 고칠 문장이 있으면 **대체 문장 제안**이 있다 (적용은 내가 한다)

## 요청
1. 감사 대상 문장을 주장 단위로 쪼개서 각각 판정해라 — 참 / 거짓 / 과장 / 근거 없음.
2. 거짓·과장·근거 없음이면 소스 근거와 함께 대체 문장을 제안해라. 톤은 짧고 쉬운 사용자용 문장으로.
3. 문장이 **내부 구현 설명**(사용자가 알 필요 없는 속사정)이면 그것도 지적해라.
