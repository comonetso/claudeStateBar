# codex_rescue

Claude가 막혔을 때 Codex에게 두 번째 시선을 받는 스킬입니다.

요청서를 쓰고, Codex를 부르고, 답을 회수해 검토하는 과정이 전부 자동입니다. 무언가를 복사해 붙여넣거나 "다 끝났다"고 알려줄 일이 없습니다.

## 무엇을 하나

Claude가 막힌 문제를 문서 한 장으로 정리해 Codex CLI에 넘깁니다. 요청서에는 원본 파일의 실제 경로와 "직접 열어보라"는 지시가 들어갑니다. Claude의 가설은 뒤쪽에 짧게만 붙습니다 — 앞에 두면 Codex가 그 시선 안에 갇히기 때문입니다.

Codex가 답을 파일로 남기면 Claude가 자동으로 깨어나 읽고 검토합니다. 분석이 도는 동안 다른 작업을 계속 지시해도 됩니다 — 하신 말이 Claude에게 시키는 일인지 Codex에게 넣을 말인지는 Claude가 판단하고, 애매하면 한 줄로 여쭙니다.

Codex는 자문역이라 코드를 고치지 않습니다(수정 모드는 예외). 다만 저장 권한 자체는 있으므로, 응답 파일 말고 무엇이 바뀌었는지 스크립트가 파일시스템을 직접 훑어 보고합니다. 전제를 깬 변경이 있으면 Claude가 사용자에게 알리고 지시를 받습니다 — 임의로 되돌리지 않습니다.

## 쓰는 법

말로 하면 됩니다. 정해진 키워드가 아니라 뜻으로 알아듣습니다.

```
/codex_rescue                     지금 막힌 것을 알아서 특정해 물어본다
/codex_rescue 분석해줘             Claude 가설을 Codex가 반박한다 (코드 안 고침)
/codex_rescue 리뷰시켜             바뀐 코드를 리뷰한다 (git diff 기준)
/codex_rescue 분석하고 수정시켜     Codex가 직접 코드를 고친다 (확인을 한 번 받는다)
/codex_rescue 코덱스와 대화해       짧게 묻고 짧게 받는 핑퐁 (질문이 무거우면 그만큼 느려집니다)
/codex_rescue 다시 물어봐           직전 분석에 되묻는다
/codex_rescue help                도움말
```

한 번 받고 끝이 아닙니다. 답을 검토한 뒤 다시 물을 수 있고, Claude가 좁게 해석했으면 Codex가 그걸 교정해 줍니다(최대 11턴).

## 도는 중에 끼어들 수 있습니다

분석이 진행되는 동안 말을 걸면 그대로 Codex에게 전달됩니다. Codex는 하던 일을 버리지 않고, 이어가면서 그 내용을 반영합니다.

```
"아 참, 그 파일 서버에도 있어"
→ 그대로 전달됨 → Codex가 그 사실을 반영해 조사를 이어감
```

미리 켜달라고 할 필요는 없습니다. **분석·코드리뷰·수정**은 항상 켜져 있습니다. 다만 이미 끝난 작업에는 넣을 수 없습니다 — 그건 "다시 물어봐"로 갑니다. 수정 중에 끼어들어도 이미 고친 파일은 되돌아가지 않고, 그 뒤부터 반영됩니다. 되묻기·핑퐁에는 이 기능이 없습니다.

코드리뷰는 요청서를 자동으로 만들어 Codex 공식 리뷰 기준으로 돌립니다. 한도로 끊겨도 찾은 지적까지는 남고, 결과에 되물을 수 있습니다. "예전 방식으로"라고 하면 Codex 전용 리뷰로 돕니다(끼어들기·중간 저장·되묻기 없음).

수정 결과를 받은 뒤 "이것도 고쳐"라고 하면 같은 대화를 이어서 고칩니다. 턴마다 확인을 한 번 받습니다.

## 요구사항

Codex CLI가 설치돼 있고 로그인돼 있어야 합니다.

**Node 20 이상은 끼어들기에만 필요합니다** — 스킬 전체가 아닙니다. Node 22 이상은 그냥 되고, Node 20은 실행 플래그가 필요한데 스크립트가 알아서 붙입니다. Node 18은 안 됩니다. 스크립트가 버전 번호를 믿지 않고 직접 확인합니다. 안 되면 끼어들기만 빠지고, 실행 전에 알려줍니다.

`docs/codex_rescue/` 아래에 스탬프와 슬러그로 짝지어 쌓입니다. 없으면 자동으로 만듭니다.


핑퐁만 프로젝트 루트 기준이고 나머지는 현재 폴더 기준입니다.

## 설치

Claude Code 플러그인으로 설치하십시오. Claude Code 안에서 `/plugin marketplace add comonetso/claudeStateBar` 를 실행한 뒤 `/plugin install codex-rescue@comonetso` 를 실행하고 Claude Code를 다시 열면 됩니다. 업데이트는 `claude plugin update codex-rescue@comonetso` 로 받습니다.

이 폴더를 `~/.claude/skills/codex_rescue/` 로 복사하는 방법도 여전히 동작하지만, 그 사본은 업데이트가 자동으로 오지 않아 더는 권하지 않습니다. 그렇게 설치해 두셨다면 플러그인을 설치한 뒤 그 폴더를 지우십시오. 둘 다 두면 같은 이름의 스킬이 두 개가 됩니다. 필요한 것(Codex CLI · Node 버전)과 수동 설치 파일 목록은 [설치 가이드](https://github.com/comonetso/claudeStateBar/blob/main/docs/codex-rescue-guide.ko.md#0-설치)에 있습니다.

`/skill_cp_install deploy`는 **별개의 다른 스킬**입니다. 자신의 `~/.claude/skills/`·`~/.claude/commands/` 전체를 SSH로 자신의 원격 서버에 밀어 넣는 작업 환경에서 쓰는 것으로, `codex_rescue`를 받는 것과는 무관합니다. 대부분의 설치에서는 쓸 일이 없습니다.

## Windows에서 파일 쓰기가 실패하면

`Failed to write file ...` 이 반복되고, 같은 프로젝트인데 **특정 폴더에서만** 실패한다면 그 폴더의 소유자를 확인하십시오.

```powershell
Get-Acl -LiteralPath "<폴더>" | Select-Object Owner
```

`BUILTIN\Administrators` 가 나오면 그것이 원인입니다. 권한 목록(ACL)에 쓰기가 허용돼 있어도 실패합니다. 관리자 권한으로 아래를 실행해 복구합니다.

```
takeown /F "<폴더>" /R /D Y
icacls "<폴더>" /reset /T /C
```

⚠️ 이 두 줄은 **하위 전체에 재귀로** 걸리고, 손수 설정한 권한을 상속값으로 되돌립니다. 그 폴더에 직접 준 권한이 있으면 사라지니, 중요한 곳이라면 `icacls <폴더> /save` 로 먼저 백업하십시오. `takeown` 만으로 되는지는 확인해보지 않았습니다 — 위 조합이 실제로 복구에 성공한 절차입니다.

경로의 공백, `.gitignore` 대상 여부, 폴더 깊이는 원인이 아닙니다 — 대조실험으로 확인했습니다.

자세한 내용과 그 밖의 함정은 `SKILL.md`의 트러블슈팅 항목에 있습니다.
