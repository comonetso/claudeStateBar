# Speech providers

The **TTS, STT, Translation Provider** section in Claude State Bar settings selects a language and a separate API provider for each feature.

| Feature | Providers | Default |
| --- | --- | --- |
| Translation | Google (Gemini), OpenAI (ChatGPT), Anthropic (Claude) | Google |
| Read aloud | Google, OpenAI | Google, Zephyr |
| Dictation | Google, OpenAI | Google |

The shared language choices, in order, are Korean, English, Japanese, Chinese, Spanish, French and Arabic. Before settings are saved, the language follows Paseo's Korean/English screen language, falling back to Korean.

Expand the selected voice to see the available choices. Select a name to choose it and close the list. Preview plays a fixed sentence in the selected language without changing the selected voice; press again to stop. Preview audio is reused for that provider, voice and language while the settings screen remains open, including while the section is collapsed. The sound is AI-generated.

Each provider lists six widely used female voices: Google **Zephyr, Aoede, Callirrhoe, Despina, Kore, Leda** (gender as reported by Google); OpenAI **marin, alloy, coral, nova, sage, shimmer** (OpenAI does not publish voice genders, so these are the voices commonly described as female). A previously saved supported voice outside these lists appears first and stays selected.

Press **Save provider settings** to apply language, provider and voice changes. Settings live in `~/.paseo/claude-state-bar/speech.json` (under `PASEO_HOME` when set). Saving on the PC sends the same settings to the servers used for dictation name hints and shows each server's result. Server chats use their own daemon's settings and API keys.

Only the selected providers' required key fields are shown. **Save keys** updates non-empty fields in that device's existing `google.env`; saved values are never returned to the screen. Google uses `GOOGLE_GEMINI_KEY` for translation/dictation and `GOOGLE_TTS_KEY` for speech; OpenAI uses `OPENAI_API_KEY`; Anthropic uses `ANTHROPIC_API_KEY`. Key checks make short translation/synthesis requests and show each key's result. They do not test the microphone or dictation endpoint.

Translation storage is separate for each provider and language. Existing entries without a provider are read as Google entries, retaining their original seven-day expiry. A missing key or a failed request returns an error without changing providers.

**Translate thinking automatically** (off by default) shows thinking boxes translated from the start, without pressing Translate. Only paragraphs not already in the chosen language are translated, and the original shows briefly until the translation arrives. While it is on, each box keeps only the Original and Read buttons, and Read waits for the translation before reading it. When it is off, the buttons go back to Translate, Read and Translate and read; Translate and read shows the translation only while reading and returns to the previous view when it finishes. Chats running on a server are translated with that server's key file. A collapsed box sends nothing to translate and is translated the moment it is expanded, whether it was collapsed with Collapse all above the input or on its own. Translations already requested are still kept, and a collapsed box that is being read aloud keeps translating. Right below it, **Expand thinking automatically** (on by default) opens the box that is still thinking and lifts its height limit while automatic translation is on, so it shows without scrolling.

Models: Gemini `gemini-3.5-flash-lite` (translation), `gemini-3.8-flash` (dictation); Anthropic `claude-haiku-5-5` (translation); OpenAI `gpt-4.1-mini` (translation/dictation cleanup), `gpt-4o-mini-tts` (speech), `gpt-transcribe` (dictation).

Voice evidence: [Google Chirp 3 HD](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd), [OpenAI TTS](https://developers.openai.com/api/docs/guides/text-to-speech), [OpenAI CLI speech example](https://developers.openai.com/api/reference/cli/resources/audio/subresources/speech/methods/create).

## When the PC is offline

When the PC disconnects, Calladmin-Gabia provides the project list and manager, usage, settings screen and dictation input protection. The PC takes over again when it reconnects; each screen has one set of these contributions. Other servers do not take over, and employee daemons keep their existing behavior.

The PC sends a separate project copy, including pins and category/project order, to the same servers as dictation name hints at daemon startup and whenever those files change. The copy is stored in `~/.paseo/claude-state-bar/pc-offline-projects.json`; it is separate from each server's own project file. Failed transfers are tried at the next change or daemon startup. The fallback server needs a successfully delivered copy.

While Calladmin-Gabia is providing these screens, projects and settings are read-only. Selecting a PC project shows an offline notice; connected server projects open normally. Usage and displayed settings come from Calladmin-Gabia. Saving settings, providers, keys, names, uploading sounds, and resetting or editing project order are disabled. Automatic alert sounds, settings synchronization, layout save/load, representative-device selection and pane-maximize logging remain PC features. Dictation protection retains its existing supported-app-version limit.

## Switching the Claude provider in the same chat

When a device has at least two Claude providers in its Paseo settings (`claude` or a provider with `extends: "claude"`), its Claude chats get a **Claude 공급자** pill above the composer. It shows only an icon on every screen and turns orange when the current provider differs from the one the chat was opened with. Hovering it (or the sheet title on a phone) names the provider in use, such as **Claude 공급자: Claude (como)**. The confirmation shows **X → Y**, using the device's exact Paseo labels, such as Claude, Claude (como) and Claude (hrg). Choose any Claude provider except the current one; with two providers there is still just one switch button.

Switching stops that chat's Claude process. Your next message starts the same conversation through the selected account, preserving context and on-screen history. A reply in progress is cancelled, and Paseo may show "Claude stopped unexpectedly" once. The confirmation warns about this and shows the current context size: the first reply reads the whole conversation against the selected account's limit. Paseo's recorded provider and the name at the top remain the original ones.

The per-device record is `~/.paseo/plugin-data/claude-state-bar/accounts.json` (under `PASEO_HOME` when set) and is removed on archive. Records use provider IDs; old `team` and `personal` records still work. Both launchers read and watch the record, clear the other account's `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_OAUTH_TOKEN`, then use the selected provider's account values. Providers without these values use the default personal login. A PC login folder runs the team settings sync first; that script must accept `CLAUDE_CONFIG_DIR`. Every switchable provider must use one of these launchers. Codex and other provider families are excluded, and employee daemons have no pill.

Each Claude provider with a `CLAUDE_CONFIG_DIR` gets its own usage source, exact Paseo label (including parentheses), and independent login refresh. Its card appears after that folder is logged in. Token-only server providers still cannot supply a usage card through this source.

The public plugin has no automatic switching policy. The owner's separate launcher module allows only the designated team IDs `claude-yeogiaen` and `claude-hrg` and rotates chats currently using one of them, including a chat opened with a personal provider and switched to a team by hand: at 85% five-hour usage once the main result is in and no subagent or workflow is still running (shell commands and monitors are not waited for), or on an actual five-hour rejection without waiting for tasks. Each candidate is checked with a short Haiku request; the lowest usage must be below 85% for an idle switch or below 95% for a rejection. Failed probes keep the account unchanged. Chats using a personal provider never rotate, and nothing ever rotates to a personal provider; if both team accounts are full, they wait for reset. Set `CLAUDE_TEAM_ROTATION=0` in the launcher environment to disable it. On Claude Code 2.1.299 or later (verified on 2.1.299 and 2.1.300), a new process starts with an empty task set; other versions must emit the full background-list event before idle rotation is allowed. A switch applies on the next message and does not resend a stopped prompt. After an automatic switch, the next message carries a one-time note listing the background tasks that were stopped, so Claude can restart the ones still needed.

## Logging in to Claude again

When the Claude login lapses and a chat stops with "Failed to authenticate" or "Not logged in", a red key pill appears above that chat's composer. Pressing it has that device's daemon run `claude auth login` and returns the approval link. Open the link in any browser, phone or PC, approve it, and paste the code shown after approval to finish. The stopped message is not resent; the chat continues when you send the next message. The **Claude login** section near the top of the settings screen lets you log in again on each device at any time, and it opens with the number of stopped chats when a login has lapsed.

The login targets are that device's Claude providers that use a login file; providers sharing the same login folder (`CLAUDE_CONFIG_DIR`) are grouped. Providers that set `CLAUDE_CODE_OAUTH_TOKEN` in their env are left out because logging in again cannot fix them. A chat switched to another provider logs in to that provider's login file. The error is recognised when a turn ends with that single error line as its last reply. The login command is kept from opening a browser by itself, so open the link with **Open link** on the screen. After logging in the daemon checks that the login file was written, and the approval link and code are never logged. Employee daemons do not have this.

## Turn end time and jumping to your previous message

When Claude finishes a turn, the time it ended is added after the work time in the row of buttons below it (`Worked for 43s · 2:17 PM`). It uses the same format Paseo shows on hover: the time alone for today, the weekday within this week, and the date before that. Hovering or pressing that label no longer swaps it to the time. The time under each of your messages is always shown too; the rewind and copy buttons still appear only on hover.

Each chat gets a **내말** pill above the composer (icon only on narrow screens). Pressing it moves to your message just above what you are looking at, and each further press moves one more of your messages up. It uses the jump of Paseo's chat outline (the ticks on the left edge of the chat), so it reaches older history that has not been loaded yet. With the chat outline turned off in Paseo's settings it only moves between your messages already drawn on screen.

When you answer a question Claude asked with buttons, a card with the questions and the answers you picked stays at that spot in the chat. If you replied with a message instead of the buttons, the card says so. While Claude is still waiting for the answer, Paseo's question prompt shows as before. A message another chat sent through peer_mail is folded in the chat into a single line, "다른 대화에서 온 글 — title"; press it to show just the body. The receiving Claude still gets the full original message.

## Follow reading

Each chat gets a headphones pill above the composer. Press it and Claude's replies in that chat are read aloud from now on, paragraph by paragraph as each one finishes; the icon is green while it is on. If you select some text in one of Claude's replies before turning it on, reading starts at that paragraph and goes on through every reply after it. Without a selection, if Claude is speaking when you turn it on, reading starts at the beginning of that reply; if Claude is thinking, running a tool or idle, it starts with the next reply. It keeps reading later turns until you press the pill again or the stop button in the reading controls above the composer. Pressing another read button or the pill in another chat switches to that reading, and reloading the page turns it off. New paragraphs keep being collected while the Paseo page is hidden behind another tab or in a minimized window. The body of a thinking box is skipped, but text taken out of a thinking box is read. Like the other read buttons it reads the text shown on screen, and the pill appears only when reading aloud is available (a speech key is set and reading aloud is on in settings).

In the phone app, other apps such as YouTube are lowered to 20% of their volume while anything is being read aloud and return when reading pauses or waits for the next paragraph. The switch is **Lower other sounds while reading aloud** in the sound settings, on by default. The PC is not supported.

## Shortcuts, project menu and the compact-ready sound

On the web and the PC app, **Ctrl+Alt+Shift+F** toggles a maximized chat pane. If a pane is maximized it is restored; otherwise the pane holding the text cursor, the chat pane in view, or the first pane, in that order, is maximized. This key never maximizes the activity pane. **Ctrl+Alt+Shift+W** opens the activity panel of the current workspace. This plugin's shortcuts (switching the left pane, maximizing a pane, the activity panel and reading speed) are gathered in the **Shortcuts** section of the settings screen, where you can change them. The composer list keys (Shift+Enter, Tab, Backspace) cannot be changed or picked for another shortcut. To change one, press [Change], press the key you want, then [Save]; every screen uses the same keys. Two plugin shortcuts cannot share a key, and a key that matches a Paseo shortcut shows a warning. The keys mentioned here are the defaults.

While a message or a thinking box is being read aloud, **<** (Shift+comma) lowers the reading speed one step and **>** (Shift+period) raises it one step. The keys are taken only while reading, so during that time < and > are not typed into the composer. They are ignored together with Alt or while an IME is composing.

When the app opens or reloads, the project list on the left starts with only the active group expanded; the pinned, category and hidden groups start collapsed. On the right of a row in the active group, an orange question mark shows when a conversation in that project is waiting for your answer to a Claude question, and orange inward arrows show when a conversation is ready for its compact command. Right-clicking a project in the project list on the left (long-press on the phone) opens a menu with **이름 복사** (copy name) and **이름 바꾸기** (rename). Renaming is the same as in the manage screen; Enter saves and Esc cancels. While a server stands in for an offline PC, and on staff screens, only copy name is offered.

The usage footer orders its cards as the personal Claude, the team Claude providers (by name), then other providers such as Codex. Every card draws its bars at the same position and length, and reset times always include the date (`10/16 00:29`). Paseo keeps fetched usage for five minutes; the refresh icon next to the collapse arrow of the expanded footer fetches every card again right away. The personal Claude login is renewed before it expires, so its card stays visible even when no chat uses that account.

While the Paseo screen is hidden behind another tab or in a minimized window, the activity panel, the project counts and the Codex lists stop refreshing, and they refresh as soon as the screen is visible again. The work itself keeps running, and sounds still play.

On narrow screens (phones) the change-count pill above the composer (`+38.7k -0`) is hidden to leave room for the other pills; wide screens still show it. Sound volume can be set from 50% to 1000%; above 300%, sounds that are already loud may distort.

When the last text of a Claude reply has a line starting with `/compact 세션로그 … 가 이 세션의 정본이다`, the **compact-ready** sound plays instead of the done sound. It tells you, even while you are busy elsewhere, that the pre-compaction checkpoint (`start_compact`) has finished and the compact command is ready to copy. The default is the Windows calendar notification (Submarine on macOS); change it in the sound section of the settings screen.

## Phone push

In the Android app that wraps the Paseo web UI (`com.blueming.paseo`), two things that need your hands also arrive as phone notifications: Claude asking a question with buttons or waiting for plan approval, and a finished pre-compaction checkpoint whose compact command is ready to paste. Every conversation sends them, not only the one on screen, and the sounds still play as before. Answering the question clears its notification (also when you answer on the PC); a compact-ready notification clears when the next message starts in that conversation or the conversation is archived. Tapping a notification opens that conversation. Each machine's daemon sends its own conversations' notifications to Firebase directly, so each machine needs a service account key at `~/.paseo/claude-state-bar/fcm-service-account.json`. Machines without the key and staff daemons send nothing.
